## 二、根因

`.51` 上的真实报错（`python -c "import app.main"` 复现，尾部两段）：

```
ModuleNotFoundError: No module named 'tzdata'

During handling of the above exception, another exception occurred:
  File "C:\apps\zhuopin-recruit-agent\app\main.py", line 6, in <module>
    from app.web.server import create_app
  File "C:\apps\zhuopin-recruit-agent\app\web\server.py", line 41, in <module>
    from app.storage import job_queries
  File "C:\apps\zhuopin-recruit-agent\app\storage\job_queries.py", line 62, in <module>
    _UTC_ZONE = ZoneInfo("UTC")
zoneinfo._common.ZoneInfoNotFoundError: 'No time zone found with key UTC'
```

链条：

1. `21af03a`（2026-09-07，「全分支终审修复——UTC 时间戳中文化…」final review round 1）
   给 `app/storage/job_queries.py` 加了 `from zoneinfo import ZoneInfo`，并在
   **模块顶层**（62/63 行）求值：
   ```python
   _UTC_ZONE = ZoneInfo("UTC")
   _SHANGHAI_ZONE = ZoneInfo("Asia/Shanghai")
   ```
2. 标准库 `zoneinfo` **自己不带时区数据**。Linux/macOS 上它读系统的
   `/usr/share/zoneinfo`；**Windows 根本没有这个系统库**，标准库的唯一兜底是
   pip 包 `tzdata`。
3. `tzdata` 既不在 `requirements.txt`／`pyproject.toml` 里，也不在 `.51` 的 venv 里
   （`pip show tzdata` → `Package(s) not found`）⇒ 抛 `ZoneInfoNotFoundError`。
4. 求值在**模块顶层**，所以炸在 import 期：uvicorn 进程在日志系统初始化之前就死了
   —— 这正是 `app.log` 一行都没写、只能靠计划任务「上次结果 = 1」和手工复现定位的原因。

## 三、为什么四道闸门全没拦住

这条缺陷同时具备「本机不可见」和「依赖清单不可见」两个性质，逐道穿过：

| 闸门 | 为什么放行 |
|---|---|
| 本机单测 / 全分支终审 | macOS 有 `/usr/share/zoneinfo`，`ZoneInfo("UTC")` 正常返回。本机实测确认可用 |
| Code review | `from zoneinfo import ZoneInfo` 是**标准库**导入，读代码看不出它有平台依赖 |
| opener §一.4「`requirements.txt` 无 diff ⇒ 只 sync」 | diff 确实为空——因为**该加的那行压根没被加进去**。这道闸门检查的是"依赖清单变没变"，而事故是"依赖变了但清单没变" |
| `sync-to-server.sh` 自带远程健康检查 | ✅ **它拦住了**，报了 `HTTP 000`。这是唯一起作用的一道，也是我们知道出事的原因 |

🔴 **教训（判据可机器化）**：`requirements.txt` 无 diff **不等于**运行时依赖无变化。
纯 `sync` 的前提应当加一条：**本次发版范围内新增的 `import` 是否全部已在 venv 里存在**。
标准库导入不豁免——`zoneinfo`（需 `tzdata`）就是反例。

## 四、修复方案（⏸ 待 Shao Peishen 裁决，`.51` 发版为不可代项）

一行修复：

```
# requirements.txt
tzdata          # Windows 无系统 IANA 时区库，zoneinfo 必须靠它；⛔ 不要因为
                # "Mac/Linux 上不装也能跑" 就删掉，见 docs/findings/2026-09-08-51四次发版回滚.md
```

⚠️ **改了 `requirements.txt` 之后，下次发版就不能只 `sync` 了**——必须重跑
`deploy-server.ps1`（或在 `.51` venv 里单独 `pip install tzdata`）把新依赖装进去，
否则 sync 完还是同样的 `ZoneInfoNotFoundError`。发版程序从「只 sync」变成
「装依赖 + sync」，属于发版决定，等他拍。

**备选（未采纳，记录理由）**：把 `ZoneInfo(...)` 从模块顶层挪进函数体、或换用
`datetime.timezone.utc`。前者只是把崩溃从 import 期推迟到首个请求，治标不治本；
后者对 `Asia/Shanghai` 无解（`timezone.utc` 只覆盖 UTC，而中文化时间戳要的正是
上海时区）。**根子是缺依赖，就补依赖。**
