**为什么要测**：本项目 `requires-python = ">=3.14,<3.15"`（`pyproject.toml`，刻意收紧到

## 意外与坑（⚠️ 后续章节会被它绊到）

- **发行名 ≠ import 名**：PyPI 发行名 `wecom-aibot-python-sdk`，顶层模块名 `aibot`。
  写 `import wecom_aibot_python_sdk` 会 `ModuleNotFoundError`。本次实测中探针按候选列表
  `("aibot", "wecom_aibot_python_sdk")` 依次尝试，第一个 `aibot` 即命中，验证了这一点。
- **模块 `__version__` 不可信**：实测 `module_version_attr` 为 `"1.0.0"`，而发行版本
  （`pip freeze` / `importlib.metadata.version`）是 `1.0.2`——两者确实对不上，与 brief 描述一致。
  `requirements.txt` 钉的是**发行版本** `1.0.2`，任何"用 `__version__` 校验装对没有"的做法都会误判。
- **默认重连次数有上限**：实测读取 `aibot.WSClientOptions.__init__` 签名，
  `max_reconnect_attempts: int = 10`（默认值 10，非无限）；进一步读 `aibot/ws.py` 源码
  第 338-351 行 `_schedule_reconnect`，确认判断逻辑是 `self._max_reconnect_attempts != -1 and
  self._reconnect_attempts >= self._max_reconnect_attempts` 才停止重连——即 `-1` 表示无限重连，
  与 brief 的描述一致（本次未发现差异）。而 spec `liaison-channel-session`「断线后自动恢复接收」
  要求"自动重试**直至成功**、服务不退出"。**这是第 7 章 7.6 的接线约束**，
  ⛔ 第 1 章不实现，但第 7 章接线时必须显式把 `max_reconnect_attempts` 设为 `-1`，
  ⛔ 不许用默认值 10。
- **安装带入的传递依赖较重**：`aiohttp`、`websockets`、`cryptography`（含 C 扩展 `cffi`）、
  `pyee` 等共 16 个包，均在 PyPI 上有 `cp314` 的预编译 wheel，本次未触发任何源码编译。
  这意味着"可安装"这一判据在本机（macOS arm64）成立，但不能替代未来在目标部署环境
  （Windows）上的独立验证——判据 A 的适用范围仅限于本次实测所在平台。

## 结论

**路线结论：①**

- **①**＝ 判据 A/B/C 全过 → 采用 SDK，在 `tools/liaison/requirements.txt` 里**钉死发行版本号**
  （`wecom-aibot-python-sdk==1.0.2`）。
- **②**＝ 任一判据未过 → 按 design D8 退路，自建最小 WS 客户端骨架（只覆盖本服务用到的
  消息类型，⛔ 不做通用 SDK）。

⛔ 本文件里**有且只有一行**以 `**路线结论：` 开头的文本。多写一行会让 Task 3/4 的分支
判定失去唯一依据。

⛔ 无论结论是哪条，都**不放宽 `requires-python`**（design D8 明文禁止）——放宽会把整个
产品的版本对齐前提改掉，代价与本工具的收益完全不成比例。本次实测未涉及、也未触碰
`pyproject.toml`。
