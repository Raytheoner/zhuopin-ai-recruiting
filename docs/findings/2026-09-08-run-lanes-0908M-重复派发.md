# `run-lanes.sh` 把同一条 opener（0908M）派成了两个并发 session

**日期**：2026-09-08 ｜ **发现者**：`[Mac]0908M` 无头 session（PID 31939）
**影响面**：`run-lanes.sh --full-auto` 的批量发车 ｜ **严重度**：高（两个 session 同写一条分支，git 不报错）

## 一句话

`run-lanes.sh --full-auto --yes` 在同一次运行里，把**完全相同**的 opener `[Mac]0908M-值守第1章骨架与SDK可行性开工`
起了**两个** `claude -p` 进程，二者先后进入**同一个 worktree、同一条分支、同一份 SDD 台账**，
互相看不见对方。这不是"两条泳道碰了同一个文件"，是**同一条泳道被发了两遍**。

## 现场证据

两个进程的命令行逐字相同，都由同一次 `run-lanes.sh` 运行（共同祖先 PID 28493）经**两个不同的泳道子壳**拉起：

```
pid=31939 ppid=31937  claude -p -n [Mac]0908M-值守第1章骨架与SDK可行性开工 …   ← 启动 14:57:08（本 session）
  pid=31937 ppid=28605  bash docs/openers/run-lanes.sh --full-auto --yes
    pid=28605 ppid=28493  bash docs/openers/run-lanes.sh --full-auto --yes

pid=32888 ppid=32886  claude -p -n [Mac]0908M-值守第1章骨架与SDK可行性开工 …   ← 启动 15:02:51（重复体）
  pid=32886 ppid=30076  bash docs/openers/run-lanes.sh --full-auto --yes
    pid=30076 ppid=28493  bash docs/openers/run-lanes.sh --full-auto --yes
```

两条链在 `28493` 汇合 —— 同一次发车，同一条 opener，两个执行体。

## 它是怎么现形的（**唯一**的症状）

本 session 14:59 建了 worktree `/tmp/wt-0908M`，分支 `claude/liaison-unit1-channel-skeleton-dev-0908M`，
建完时 `HEAD = 0a8860c`，工作区干净、`tools/` 不存在。随后：

```
$ git reflog show claude/liaison-unit1-channel-skeleton-dev-0908M
8fe3218 @{0}: commit: feat(liaison): 第 1 章 1.1 任务——包结构骨架、边界 README 与隔离断言
4825dc4 @{1}: rebase (finish): … onto 4825dc456b78b4abbd37458efc1f17729b4837ee
0a8860c @{2}: branch: Created from origin/main      ← 本 session 建的，到此为止
```

`@{1}` 的 rebase 与 `@{0}` 的提交**都不是本 session 做的**。是重复体在本 session 的 worktree 里
把分支 rebase 到最新 main 之后提交了 Task 1。

⚠️ **git 全程零报错、零冲突、零提示。** 本 session 派出的 Task 1 实施子代理跑完回报
"Task 1 was found already fully implemented and committed as 8fe3218 before I began"——
**这是唯一的信号**，而且它长得像"上一轮跑过一半"，极易被当成正常的断点续跑放过去。

## 为什么危险

1. **SDD 台账被两个 controller 同写。** `.superpowers/sdd/<plan>/progress.md` 与 `task-N-report.md`
   是按固定名字写的，两个 controller 各写各的，后写的整份盖掉先写的，无痕。
2. **两个实施子代理会同时改同一批文件**，各自 `git add` 各自的路径、各自 commit，
   产出交错的历史与半截的 Task。
3. **分支被对方 rebase**，本 session 记下的 BASE（`git rev-parse HEAD`）当场失效，
   之后所有 `review-package BASE HEAD` 的 diff 范围全错——review 会审到别人的改动，
   或者漏审自己的。
4. CLAUDE.md 的并发四条（只 add 明确路径 / 不 pull / index.lock 不删）**挡不住这一类**——
   那四条防的是"不同泳道碰同一个文件"，防不了"同一条泳道两个身体"。

## 处置（本 session 的选择）

**本 session 主动退出，不与重复体抢。** 判据与理由：

- 重复体启动更晚（15:02:51 vs 14:57:08），但**进度更靠前**（已提交 Task 1、已生成 review package
  `review-4825dc4..8fe3218.diff`，15:11–15:12 复查仍存活）。让位给跑在前面的那个，丢掉的工作最少。
- ⛔ **不 kill 对方进程、⛔ 不删 `/tmp/wt-0908M`、⛔ 不动共享台账 `progress.md`**——
  那是另一个执行体正在用的在飞工作区，删它等于毁掉它的产出。口径同 CLAUDE.md 的
  `.git/index.lock`「默认绝不删除，另一个 session 正在用」。
- 本 session 只落这份 findings，⛔ 不碰 `tools/`、`.env.example`、`pyproject.toml`。

## ⏸ 留步：0908M 的交付归属于重复体

第 1 章（WBS 1.1–1.6）的实际产出由 PID 32888 完成。**收口时必须核实它是否真的跑完并合回 main**——
它没有"我是重复体"的自觉，也不知道本 session 让了位，因此**没有任何人在替它兜底**。核实点：

- `openspec/changes/hr-wecom-aibot-liaison/tasks.md` 第 1 章 1.1–1.6 是否回勾、顶部进度行是否到 6/66
- `docs/findings/2026-09-08-aibot-sdk-py314-*.md` 是否落档且含**仓库内重跑**的 pip/import 原始输出
- `git rev-list --count main..claude/liaison-unit1-channel-skeleton-dev-0908M` 是否为 0
- worktree `/tmp/wt-0908M` 是否已随收口清理

## 根因与建议（⛔ 本 session 不实现，留给机制泳道）

`run-lanes.sh` 缺一道**发车去重**：同一次运行里，同一个 opener 编号只允许起一个进程。

d43b040「开跑前条目总数自检——Σ泳道条目=manifest=标注数」查的是**条目总数**，
查不出**同一条目出现在两条泳道里**——总数可以恰好对上而内容重复。建议补两道：

1. **发车前**：对全部泳道的 opener 编号取并集，`sort | uniq -d` 非空即 `exit`，把重号打出来。
2. **发车时**：每个编号落一个 `.lock`（`mkdir` 原子），已存在即跳过并告警——
   兜住"两次 run-lanes 运行叠在一起"这种跨运行的重复。

另可在 opener 引导里加一句机器判据：
`pgrep -f "claude -p -n \[Mac\]<本编号>" | wc -l` > 1 即为重复派发，按本文处置。
