## 零、结论先行

1. **8 页全部无统一外壳、控件回到浏览器默认样式**，与"内网产品级"的差距主要不在配色，而在
   **页面骨架、组件形态与信息可读性**（证据：`01-login`／`04-upload`／`05-list`／`06-review`／`07-prep-review`／`08-invite-issue`／`09-consent`）。
2. **两处"内部实现泄漏到界面"的真缺陷**：
   - 候选人同意页把条款 **Markdown 源码**（`#`、`**`、反引号）直接展示给候选人（`09-consent`）；
   - 业务经理题目确认页把 **rubric 的原始 JSON** 放在可编辑框里（`07-prep-review`）。
   另有字段校对页显示英文 `snake_case` 字段名、解析列表显示英文枚举值（`06-review`／`05-list`）。
3. **一个发版级隐患被实测复现**：`static/app.css` 无版本参数，浏览器缓存会让升级后的页面**半新半旧**
   （本场 IAB 实测：HTML 已是新的、CSS 还是 21 条规则的旧版；加 `?v=` 后恢复 62 条规则）。
4. 本次按**一版方向**（不给选项）完成 8 页改造；机器判据全绿：375px 真机 rc=0、全量 pytest 3825 passed。
5. 仍缺 1 条需要后端配合的呈现（字段校对页"待校对"黄底在真实数据下不显示），已登记（§七）。

## 三、发现清单（UX ＋ 可访问性）

**结构性（改造前）**

- U-1 8 页无统一外壳：没有品牌条/内容容器/卡片层，视觉重心与页面归属都读不出来（`04/05/06/07/08/09`）。
- U-2 表单与按钮为 UA 默认样式，主次动作无区分（`04/07/08/09`）；主行动（提交同意、签发、冻结）不突出。
- U-3 内部标识直出：`name/years_of_experience/...`（`06`）、`synthetic/parsed`（`05`）、rubric JSON（`07`）。
- U-4 候选人条款未渲染（`09`）：`#`／`**`／反引号原样可见，阅读体验与"知情同意"的严肃性不匹配。

**可访问性**

- A-1 字段校对行仅鼠标可点（无 `tabindex`／键盘处理）→ 已修（Enter/Space 等价，`role=button`）。
- A-2 无统一 `:focus-visible` 焦点样式 → 已修（全站控件补 2px 提示色描边）。
- A-3 表单控件缺 `label` 关联（login/upload/invite）→ 已修（`for/id` 或包裹式 label）。
- A-4 表格无表头语义问题暂未见；候选人两页 375px 无横滚（真机判据，见 §六）。
- 限制：未跑屏幕阅读器与 axe，静态结论不冒充 WCAG 合规声明。

**风险但未改（登记）**

- R-1 `resume_review` 的"待校对"黄底与徽标在真实数据下不显示：`/api/resumes/{id}/parsed` 未带
  `review_pending`（前端逻辑保留，数据源缺）——改它属后端契约，超出"不改接口语义"边界，登记待派泳道。
- R-2 样式缓存：任何 CSS 改动都可能被老缓存抵消（实测复现）→ 已用 `static/app.css?v=20261007` 解决；
  后续发版流程需在改 CSS 时同步更新该版本号（已写进 `09-UI-Design.md` §12）。

## 四、一版设计方向（单方案，不给选项）

**「内网产品级工作台」**：以共用层 `app.css` 为唯一视觉来源，给全部页面套同一套
**品牌条 → 居中内容列 → 卡片** 骨架；组件形态统一为"卡片行 + 弱化元信息 + 明确的动作按钮"；
一切**内部标识先翻译成人话再上屏**；AI 标识继续用黄色提示条（正常字号），不引第三方库、不做暗色、品牌色 `#0d6efd` 不变。

为什么这样定：审计里最大的差距是骨架与组件一致性（U-1/U-2），而不是配色；把样式收敛到共用层后，
后续 M2 工作台三页与二期页面可以直接复用，不再逐页手写样式。视觉探索（ideate/位图方向）本场不需要——
方向是工程化的统一，不是风格二选一。

## 六、实施与复核（机器判据，实测尾行）

1. **375px 真机判据**（`scripts/ui_narrow_check.mjs`，本机 Chrome 152 无头）：
   - 改造后：`rc=0`；`interview_consent.html scrollWidth=375 按钮=327/327/327`；
     `interview_invite_issue.html scrollWidth=375 按钮=305/305`。
   - 过程记录：首跑回红（303/281 < 阈值 300）——根因是既有窄屏规则给 `body` 加 12px 内边距、
     新 `.page` 又加 12px，叠加把按钮可用宽度吃掉；修法＝窄屏 `.page` 只留纵向内边距＋`.btn` 用 `border-box`，
     复跑 `rc=0`（数字见上）。
2. **pytest**：
   - opener 指定子集（static/candidate-narrow/list/review/upload/invite-e2e）＋相邻回归：**65 passed**；
   - 全量：**3825 passed, 10 skipped**（两轮，均在全部前端改动后）。
3. **AI 标识仍在**：`grep -c "AI 自动抽取\|AI 生成"`：`resume_list=1`、`resume_review=1`、
   `interview_prep_review=2`、`index=10`（其余页面原本就没有这两句，无回归）。
4. **样式版本链路**：`14-final-*` 截图取自加载 `app.css?v=20261007`（62 条规则）的真实页面；
   修复前后对比截图保留在 `09-consent` ↔ `14-final-consent` 与 `07-prep-review` ↔ `14-final-prep`。

## 七、未做 / 仍缺（含证据限制）

1. **R-1 待校对黄底**：需要 `/api/resumes/{id}/parsed`（或其他只读端点）带出 `review_pending`，
   属后端契约变更，⛔ 本场不改；建议随 M2 U5 或一条小泳道处理（前端逻辑已就绪，只缺数据）。
2. **rubric 的满分不可编辑**：本场只把"维度名"做成可读输入，`max_score` 保持原值回写；若要可编辑
   需后端契约讨论（登记，不改）。
3. **视觉探索未做**（ideate/ImageGen）：方向是工程化统一，非风格二选一；如后续要做品牌化视觉稿可另开。
4. **a11y 未跑真实辅助技术**：只做 DOM/静态级；未声明 WCAG 合规。
5. 桌面截图为 1280 视口（IAB 默认）；IAB 的 viewport 覆盖在本环境不生效（实测 `clientWidth` 恒 1280），
   故 375px 的**数值与截图**以 `ui_narrow_check.mjs` 为准（真实 Chrome 375×812）。
