# 测试网络闸门被本机代理绕过（TD-36 落地时实测到的一次真实外发）

**日期**：2026-09-09 ｜ **来源**：`[Mac]0909AC`（TD-19 适配 + TD-36 隔离）

## 一句话

给 `tools/liaison/tests` 装的"⛔ 不许触网"闸门**按主机名判回环放行**，而本机
`HTTPS_PROXY=http://127.0.0.1:<port>`——建连打到回环、被放行、再由代理转发出去。
**闸门全绿，流量照常出去。**

## 现场（实测，非推演）

TD-19 的适配写完后，为核对「`python -m tools.liaison` 不再因表面校验拒启动」，
在**装了闸门**的环境里跑了一次真实入口（假凭据 `fake-bot`/`fake-secret`）。SDK 日志：

```
[AiBotSDK] [INFO]  Connecting to WebSocket: wss://openws.work.weixin.qq.com...
[AiBotSDK] [INFO]  WebSocket connection established, sending auth...
[AiBotSDK] [ERROR] Authentication failed: errcode=853000, errmsg=invalid bot_id or secret,
                   hint: [17889592050409416719...], from ip: 61.160.125.186
```

`errcode=853000` 是**企微服务端返回的**——连接确实建立了、认证帧确实发出去了。
这正是 TD-36 描述的那件事，只是发生在"已经装了闸门"之后。

⚠️ **这次外发是真实发生的**：一次到企微生产端点的 WebSocket 建连 + 一次失败认证。
未使用任何真实凭据，无数据外泄；但它证明当时的闸门是个哑巴。

## 根因，两层

1. **回环放行 + 本地代理 = 没有闸门。** 闸门按 `host` 判：`127.0.0.1` 放行（本地
   socket 用例要用它）。开发机上的代理恰好就监听在 `127.0.0.1`，于是**每一个**外部
   连接都以"回环"的形状通过闸门。
2. **只清 `*_PROXY` 环境变量不够。** `websockets` 17.1 走
   `urllib.request.getproxies()`（`websockets/proxy.py:118`），该函数在 macOS 上
   **还会读系统代理设置**（`_scproxy`）。实测清掉 8 个大小写变量之后，连接依旧从
   `127.0.0.1:<port>` 出去。

## 处置（已落地）

`tools/liaison/tests/netguard/sitecustomize.py`：

- 装闸门前先**摘代理**：`os.environ` 里 8 个 `*_proxy` 变量全 pop，并把
  `urllib.request.getproxies` / `proxy_bypass` 摁成"没有代理"；`uninstall()` 原样还回；
- 闸门本体不变：非回环的 `getaddrinfo` / `connect` / `connect_ex` 一律 raise；
- ⛔ **没有**改成"把 127.0.0.1 也拉黑"——本地 socket 用例要用回环，根因是代理不是回环。

判据用例 `test_the_self_check_never_reaches_the_network` 因此**加了第二个探针**：
除裸 socket 外，再用 **`websockets`（SDK 真正用的那条栈）**打一次
`wss://example.com/ws`，必须被拦下。只验裸 socket 的话，上面这个洞会一直报绿。

## 给下一个人的判据

**验证"测试不触网"时，⛔ 不许只验裸 `socket`。** 必须用**被测代码真正用的那个客户端栈**
打一次，并且先确认本机有没有 `127.0.0.1` 上的代理——
`env | grep -i proxy`、`scutil --proxy`（macOS）。

⚠️ 8.6 由 Shao Peishen 亲自跑真实建连时，环境里有这个代理是**正常且需要的**
（企微端点要出网）。本闸门只在 pytest 起的进程里生效，⛔ 不影响他手工跑
`python -m tools.liaison`。
