## 观察项一：漏消息告警是否误报

- **告警文本**：`tools/liaison/alerts.py` 的 `ALERT_RESEND_SENTENCE = "该时段消息可能未收到、请重发"`，在中断→恢复窗口（`liaison_outage_window`）关闭时触发。
- **查法（命令）**：
  ```
  grep -c "该时段消息可能未收到" data/liaison/logs/launchd.err.log
  sqlite3 "file:data/liaison.db?mode=ro" "SELECT id, started_at, recovered_at FROM liaison_outage_window ORDER BY id DESC LIMIT 5;"
  ```
  「误报」判据：某条窗口记录的中断时长明显短于正常冷启动噪声（例如 <10 秒的瞬时抖动）却仍产生了一条告警，或告警触发时实际没有消息被漏收（可用 `liaison_message.received_at` 落在该窗口区间内核对，命中任何一条即说明确有消息经过、不算误报）。
- **09-17 基线值**：`launchd.err.log` 累计命中 **15 次**（含历次服务重启、断网复验产生的噪声）；`liaison_outage_window` 累计 **17 行**。观察期内看**增量**，不是累计总量。

## 观察项二：限流是否被触发

- **机制**：`tools/liaison/notify/ratelimit.py` 的 `TokenBucket`（群 webhook 令牌桶），`get_group_webhook_bucket()` 全局单例。
- **查法（命令）**：
  ```
  grep -c -i "ratelimit\|rate limit\|限流\|backoff" data/liaison/logs/launchd.err.log
  ```
  ⚠️ 当前群 webhook（`HR_LIAISON_GROUP_WEBHOOK`）尚未配置（见 `docs/findings/2026-09-17-8.6与8.7实证核验.md` §2.3），回推链路 0 次真实投递 ⇒ 限流在配置就绪前**结构上不可能触发**。观察窗内若该项持续 0，不代表限流逻辑本身没问题，只说明触发条件（真实回推）尚未成立——**不得**据此判定限流机制"已验证正常"。
- **09-17 基线值**：`launchd.err.log` 命中 **0 次**（预期内，因回推链路未接通）。

## 观察项三：归档是否有重名冲突

- **机制**：归档叶子路径固定为 `<msgid>__<安全文件名>`（`tools/liaison/archive.py`），`msgid` 是 `liaison_message` 主键（`PRAGMA table_info` 确认 `pk=1`），结构上不可能有两条不同消息共享同一个 `msgid` 前缀。
- **查法（命令）**：
  ```
  sqlite3 "file:data/liaison.db?mode=ro" "SELECT COUNT(*) - COUNT(DISTINCT msgid) FROM liaison_message;"   -- 应恒为 0
  find data/liaison/archive -type f | sed -E 's#.*/([^/]+)__.*#\1#' | sort | uniq -d               -- 应为空
  ```
- **09-17 基线值**：`liaison_message` 无重复 `msgid`（差值 = 0）；归档目录当前 **3 个文件**，前缀去重后无重复。
