## 二、四种可能，逐条排除

### ① `ledger_path = md_path.parent / LEDGER_FILENAME` 在相对路径调用下解析到了别处 → ✅ **这就是真因**

`md_path.parent` 是**相对**的：`Path("docs/跟进信/x.md").parent` ＝ `Path("docs/跟进信")`，
按**进程 CWD** 落地。交付给他的命令（`docs/openers/0909AD-跟进信群发CLI.md` §四）逐字是：

```
./venv/bin/python -m tools.liaison send-followup --md "docs/跟进信/人事部-…md" … --send
```

**全是相对路径，且不带任何 CWD 守卫。** 而 `bf63e7a` 把 `docs/跟进信/` 三件套入了版本库
之后，`git worktree` 的每一个副本里都有同名同内容的 `docs/跟进信/README-跟进信清单.md`。
⇒ 在任何一个 worktree 里跑这条命令，`--md` 找得到、信件内容逐字相同、**消息照发不误**，
回填也照做不误——只是落在**那个 worktree 的副本**上。

**旁证（决定性）**：把 `.claude/projects/` 下**全部** 67 份会话记录扫了一遍，
`send-followup` 带 `--send` 的**真实执行一次都没有**（9 处命中全是源码文本或本次的 grep 本身）；
渲染后的成功行 `已发送并回填台账：人事部#1` 在整个 `~/.claude/` 里**零命中**；
`~/.zsh_history` 里也没有。⇒ 那一次是他在 CC 之外的某个 shell 里跑的，**其 CWD 已不可回溯**——
而"CWD 不可回溯 ⇒ 回填目标不可回溯"，正是这个缺陷的完整形状。

**残留副本佐证**：现存 8 份台账副本逐一核过，没有任何一份带着 CLI 写下的回填
（主工作区／`wt-0909AK`／`td39-…` 三份的终态全部来自 `f9a0aaa` 这个人工提交，
`git status` 干净、无未提交改动）。写坏的那份多半随它所在的 worktree 一起被删掉了——
**这本身就是最强的一条论据：没有那行绝对路径，事后连"写到哪去了"都查不出来。**

### ② `` f"`{number}" `` 前缀匹配碰上带括注的编号列会不会漏 → ❌ 排除

拿 `bf63e7a` 的**真实台账原文**喂给纯函数复现：

```
extract_number -> '人事部#1'
changed -> True
NEW ROW: | `人事部#1` | 2026-09-09 | 汤丽萍 | AI 招聘值守机制启用与配合方式（欢迎信／机制版）：需求确认怎么配合、系统灰度中暂不用改习惯、请定反馈形式与节奏 | 决策点 a 无硬截止，不催 | `✅ 已推送 2026-09-09` |
```

`` `人事部#1（待发，暂不占号）` `` 命中 `` `人事部#1 `` 前缀，括注被 `_PARENTHETICAL` 去干净，
产出与人工手写的终态行**逐字一致**。

**更强的一条结构性排除**：即使没命中，`compute_backfilled_ledger` 会抛 `LookupError`，
调用方**在发送之前**就 `return EXIT_BAD_ARGS`。⇒ 若②成立，**消息根本发不出去**。
消息发出去了 ⇒ ② 必不成立。同理排除"台账文件找不到"（也在发送前 return）。

### ③ `cells[-2]` 在本项目列数下指错列 → ❌ 排除

清单表 6 列（编号｜日期｜收信人｜主要事项｜交期要点｜发送状态）。
`"| a | b | c | d | e | f |\n".split("|")` ＝ `['', ' a ', …, ' f ', '\n']`，
`cells[-2]` ＝ 第 6 列 ＝ 发送状态，`cells[1]` ＝ 编号列。两者都指对。
§2 的逐字复现已经把这条一并证死。

### ④ 写盘那步没执行到 → ❌ 排除

`ledger_path.write_text(...)` 在 `send_markdown` 成功之后**无条件**执行，中间没有任何分支。
而能走到发送，前提是 `changed is True`（`not changed` 会在发送前 return 0）。
⇒ **只要 `--md` 指向的是主工作区那份台账，主工作区那份就一定会被改写。** 它没被改写
⇒ `--md` 指向的不是它。这条推理直接把结论逼回 ①。

## 六、教训

**「回填成功」和「回填到了你以为的那个文件」是两件事，而后者以前没有任何输出。**
一条会**改文件**的 CLI，必须自报它改的是哪个**绝对**路径——相对路径在多 worktree 仓库里
等于没报：`docs/跟进信/README-跟进信清单.md` 在每个副本里都存在、都长得一模一样。
这类故障的症状是「命令说成功了、你要的效果没出现」，⛔ 不报错、⛔ 不失败，
只能靠**事后翻 mtime** 发现——而那已经是运气了。
