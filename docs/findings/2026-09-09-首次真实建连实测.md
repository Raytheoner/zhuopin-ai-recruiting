## 5 · 根因（已定位到行，⛔ 非推测）

`aibot/types.py:49`：

```
heartbeat_interval: int = 30000
"""心跳间隔（毫秒），默认 30000"""
```

`aibot/ws.py:285,299`：日志打 `interval: {self._heartbeat_interval}ms`，实际 `await asyncio.sleep(self._heartbeat_interval / 1000)`。

我方 `tools/liaison/session_client.py:37`：

```
DEFAULT_HEARTBEAT_SECONDS = 30
```

在 `build_ws_options`（同文件 118–131 行）原样传给 `heartbeat_interval=` ⇒ SDK 解读为
**30 毫秒**。命名里的 `_SECONDS` 与 SDK 的毫秒契约对不上，且**类型相同、无任何报错**。

⚠️ **同一形状的第二处未爆但同样可疑**：`reconnect_interval` 默认 `1000`（毫秒 = 1 秒）。
本模块目前没传它，故未受影响；但 `session_client.py:22-25` 的 `MAX_BACKOFF_SECONDS = 30.0`
注释写着「封顶值与 SDK 内置退避的封顶取同一个数」——那个「同一个数」是在两种单位下比的，
结论不成立。还 TD-38 时一并复核。

**探针表面 vs 代码常量的一致性**：`EVENT_CONNECTED="connected"` / `EVENT_DISCONNECTED="disconnected"`
与 SDK 实际 `emit()` 点一致（`client.py:62,70`），`client.run` 为同步可零参调用，
`verify_client_surface` 全部通过 —— **表面校验这一层没有问题**，本次卡点不在表面契约，
而在一个**类型相同、单位不同**的参数上，那正是表面校验按设计看不见的盲区。
