## 最可能的根因（**假说，未定论**）

`run-lanes.sh:615` 在接续下一轮前会跑 `git pull --rebase --autostash`。
`mark_done()` 写的 ✅ 标注**是未提交的工作区改动**（此刻 `git status` 仍显示 `OP-0820-全量编排.md` 为 `M`）。
多条泳道各自的 `--autostash` 循环互相叠加时，晚于某次 stash 快照写入的标注会在 pop 时被旧内容盖回去，
于是下一轮重扫又把已完成条目看成待执行。

`0908R` 与 `0908S` **都恰好是"跑完即被标注、随后又被重派"** 的条目，两条独立样本指向同一机制。

⚠️ 这是假说。要坐实需要 `run-lanes.sh` 在每轮重扫前后各打一次
`grep -c '^>[[:space:]]*泳道：' "$PLAN"` 并入日志 —— 现在没有这个观测点，无法回溯判定。
