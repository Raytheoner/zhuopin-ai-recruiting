# P5 启动底座实测：`claude -p` 首轮上下文分层测量（2026-09-16，`0916G`，只量不改）

> 方法：每个实验全新会话、只问一句「只回复 OK」，`--output-format json`，首轮上下文 = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`。单样本，非多次取均值——数值受当时 prompt 缓存命中状态影响，见下方注意事项。脚本：`/tmp/p5/measure.sh`（scratchpad，未入库）。

## 一、CLI 开关核验

`claude --help` 命中：`--strict-mcp-config`（仅用 `--mcp-config` 指定的 MCP，不给 `--mcp-config` 时等效于不加载任何 MCP）、`--disable-slash-commands`（禁用全部技能/斜杠命令）、`--mcp-config`（本次未使用，跳过依赖它的实验变体）。三者都存在，未跳过任何实验。

## 三、推算行

| 分层 | 算法 | 值 |
|---|---|---:|
| MCP | E0 − E1 | ≈ **1480** |
| 技能清单（斜杠命令/skills 列表） | E0 − E2 | ≈ **−1763**（负值，见下方说明） |
| 项目层（CLAUDE.md ＋ 项目技能 ＋ 插件） | E0 − E4 | ≈ **24851** |

⚠️ **技能清单这一行是负的**：E2（禁用斜杠命令）反而比 E0 基线多花 1763 token，不是"技能清单省了钱"。查了各实验的 `cache_read`/`cache_creation` 明细：E0/E1 命中了 30909 token 的既有缓存（`cache_read_input_tokens=30909`），说明它们的 system prompt 前缀和之前某次调用一致；E2 的 `cache_read_input_tokens=0`、全部 54574 token 都是新建缓存——`--disable-slash-commands` 改变了 system prompt 的结构（不是单纯"少了一段"，而是整段位置/组织变了），导致前缀完全无法复用旧缓存，新建缓存的绝对量反而更大。**这条差值反映的是"改开关导致缓存失效的一次性成本"，不能直接读作"技能清单常态多花多少"**——需要多次重复测才能把缓存效应和真实内容量分开，本轮只量一次，不下"技能清单更贵"的结论，只记录现象。

## 五、结论

1. **占比最大的三块**（按绝对增量排序，技能清单那行因上述缓存伪影不计入排名）：Desktop 独有开销 ≈30.2k（最大）＞ 项目层（CLAUDE.md＋项目技能＋插件）≈24.9k ＞ MCP ≈1.5k。
2. **无头泳道用不到**：`grep -l 'mcp__' .claude/handoff/lanes-2026091*/*.log` 对本仓库唯一一批带日志的批次（`lanes-20260916-113021`，仅 1 条 `0916E` 日志）**零命中**——样本内无头泳道没调用过任何 MCP 工具，MCP 这块判定"无头泳道用不到"（但样本量=1，仅供方向参考）。项目层（CLAUDE.md/项目技能/插件）判定**不是**"用不到"——无头泳道同样在仓库工作目录里跑，同样会加载项目 CLAUDE.md，这块开销对无头泳道同样存在，不能整体关掉。Desktop 独有那部分按定义就是无头泳道没有的固定开销，不属于"可关掉"的范畴。
3. **建议 Phase 5 先动哪一块**：先动 MCP——无头泳道实测用不到，且 E1 比 E0 少花约 1.5k token，方向和预期一致，可以给无头泳道（`run-lanes.sh` 起的会话）默认加 `--strict-mcp-config`。项目层和 Desktop 独有开销更大，但涉及功能取舍（哪些插件/技能真正不需要），需要人工确认清单后再动，本轮不改任何配置。

**四块之和（11.7k）与整体（24.9k）差约 13.2k，未被本轮 F0–F4 覆盖**——F5 是完整仓库根，还包含 F1–F4 没纳入的部分：`.claude/handoff/`（1.1 MB，79 个历史交接文件）、`.claude/settings.local.json`（F4 只测了最小插件声明，未测本机真实的 `settings.local.json` 含 hooks／permissions 全量）、仓库根 `README.md`／`00`–`07` 编号文档／`.agents/`／`.superpowers/` 等。这部分本轮未拆分测量，留作后续 Phase 的候选。

**E2 定案**：F6 − F5 = 54519 − 52759 = **+1760**（`--disable-slash-commands` 反而多花约 1.76k token）。F5、F6 在同一次运行中背靠背测得，中间项目文件无任何改动，因此这个正差值**不是"两次测量间项目状态变了"**，而是 `--disable-slash-commands` 这个开关本身真实地增加了 system prompt 体积（与 0916G 报告 E2 的方向一致，本轮用干净的两次取二方法法复测，排除了单次测量的缓存伪影，结论坐实：**该开关不能用来省 token，反而更贵**）。

**CLAUDE.md 瘦身后 F5 复测**：瘦身前 F5(r2)=52759，瘦身后 F5-after(r2)=52462，**差 297 token**（仅搬走 3 行「为什么/实证」叙述，KB 从 23.3→22.5，降幅与搬运量成正比，符合预期；量级验证了「大头在内容量而非行数」，要继续压缩需要动结构性大段而非零星例句）。

## 七、未解释开销定位（0916I）

方法同六：连跑 2 次取第 2 次。

| 实验 | 内容 | r1 | r2（取用） |
|---|---|---:|---:|
| G1 | 全新空目录 ＋ `git init` ＋ 拷入 `CLAUDE.md` | 38086 | 38088 |
| G3 | 仓库根的干净 `git worktree add` 检出（无未跟踪文件、无 handoff、`settings.local.json` 被 gitignore 排除在外） | 52474 | 52476 |

**G2（禁用 auto memory）未能实测**：`claude --help` 无专用禁用项（仅 `--bare`，但它连 CLAUDE.md 自动发现一并关掉，与本项候选不纯净，未采用）；改用预案的「重命名 `memory/` 目录」法时，因该目录正是**本会话自己的**项目 auto memory，被安全沙箱的自我修改防护拦下（`[Self-Modification]`），未执行、未强行绕过。改用静态字节估算替代：`memory/MEMORY.md`（本会话实际加载的唯一部分，其余 7 个记忆文件仅按需召回、不计入每轮固定开销）1602 字节 × 0.447 token/byte ≈ **716 token**，远小于 13.2k，可排除 auto memory 作为主因。

**比对与归因**：
- G1(r2)=38088 对照 F1(r2)=38108：差 **-20**（噪声内）——空目录里单纯"是不是 git 仓库"本身不加开销。
- G3(r2)=52476 对照 F5-after(r2)=52462：差 **+14**（噪声内）——干净 worktree（零未跟踪文件）与真实仓库根（含 `_to_delete/` 等未跟踪目录）几乎相同，说明**未跟踪文件/目录不是 13.2k 的来源**，且此前 §六 归因里列的 `.claude/handoff/`（1.1MB）、`.superpowers/`（1.3MB）、`.agents/`（76KB）等大体积目录并未被整体注入 system prompt（否则数值会远超 13.2k）。
- G3 − F0 = 52476 − 27807 = **24669**，与四块之和 11688 相减 = **12981 ≈ 13.0k**——与原始未解释量几乎一致，且这次是在**全新路径、零 auto memory 命中、零未跟踪文件**的干净 worktree 里测得，排除了"项目记忆"与"未跟踪清理"两个候选。

**新假说（量级吻合，未直接读取 system prompt 原文验证）**：G3 是 488 个 git 跟踪文件的完整检出（`git ls-tree -r HEAD` 计数），跟踪文件路径名总字节数 28917B。按 CLAUDE.md 已验证的 0.447 token/byte 比例换算 ≈ **12930 token**，与上面测得的 12981 未解释量几乎重合（差 51，噪声内）。最贴近数据的解释是：system prompt 里包含与仓库跟踪文件规模成正比的一段内容（很可能是项目文件树/路径清单一类的环境信息），文件越多这块越大，而不是某个固定目录被整体读入。

**能不能在仓库内治理**：能，但要动的是「跟踪文件总数」而不是某个已知大目录——`claude --help` 未发现可配置文件树深度/裁剪的开关，治理手段落回**减少仓库根跟踪文件规模**（历史 `.claude/handoff/` 交接文件归档合并、`docs/openers/归档/` 之外还有没有可再合并的散落文档），跟踪文件每减少约 35 个（≈2KB 路径文本）预计省约 1k token；无法通过 CLI 参数一次性关闭。
