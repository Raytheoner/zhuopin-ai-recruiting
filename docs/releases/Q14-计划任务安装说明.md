# Q-14 每日快照计划任务——安装说明（发版 ② 用）

> 状态：✅ **已在 `.51` 装好**（2026-09-17 22:06 CST，`[Mac]0917BB`，G3 Q-28 答「发」）；执行记录 `docs/releases/2026-09-17-发版二与R9执行记录.md`。本文保留为重装／回滚手册。
> 对应 `docs/releases/2026-09-发版清单-51.md` §三.2；G3 行见 `docs/roadmap/定夺队列.md`。

## 一、装什么

| 项 | 值 |
|---|---|
| 执行体 | `C:\apps\zhuopin-recruit-agent\scripts\snapshot_data.py`（随 `sync-to-server.sh` 的 `scripts` 白名单一起上，⛔ 不改白名单） |
| 解释器 | `C:\apps\zhuopin-recruit-agent\.venv\Scripts\python.exe`（只用标准库 `sqlite3`／`shutil`，⛔ 不装任何包） |
| 计划任务名 | `ZhuopinDailySnapshot` |
| 触发 | 每日 03:00，SYSTEM 账户，最高权限 |
| 输出 | `C:\apps\backups\daily-<yyyyMMdd-HHmm>\`：`demo.db`（SQLite backup API 拷出，integrity ok）＋ `audit\`＋ `candidate_outbound.switch`＋ `manifest.json` |
| 保留 | 最近 14 份 `daily-*`；发版前手工快照（`20260903-1003` 这类）**永不触碰** |
| 日志 | `C:\apps\backups\snapshot-last.log`（每次覆盖；退出码非零即失败） |

为什么不用 `Copy-Item data\`：服务在线时 `demo.db-shm` 被占用，整目录复制会 `IOException` 中断（09-08、09-09 两次实证）。`sqlite3.Connection.backup()` 在 WAL 模式下与在线写事务并存，拷出的是最近一次已提交状态——单测 `tests/test_snapshot_data.py::test_backup_succeeds_while_another_connection_holds_write_txn` 覆盖了这一点。

⚠️ 计划任务默认工作目录是 `System32`，所以 `/tr` 里全部用绝对路径，⛔ 不依赖相对 `data`。

## 二、安装（在 `.51` 上跑，Mac 侧 ssh 包装）

**0. 前置**：`sync-to-server.sh` 已把含 `scripts/snapshot_data.py` 的 main 推到 `.51`（发版 ① 之后合的 main 需再推一次，`ssh zp51 "dir C:\apps\zhuopin-recruit-agent\scripts\snapshot_data.py"` 能看到即可）。不重启服务。

**1. 先手工跑一次**（不装任务，先证明脚本在 `.51` 环境能跑通）：

```
ssh zp51 "C:\apps\zhuopin-recruit-agent\.venv\Scripts\python.exe C:\apps\zhuopin-recruit-agent\scripts\snapshot_data.py --data-dir C:\apps\zhuopin-recruit-agent\data --backup-root C:\apps\backups --keep 14 & echo EXIT=%ERRORLEVEL%"
```

判据：末行 `EXIT=0`，且 stdout 有 `备份 demo.db → C:\apps\backups\daily-…\demo.db（N 页，integrity ok）`。非零 ⇒ 停，不装任务，把输出贴进 findings。

**2. 注册计划任务**：

```
ssh zp51 "schtasks /create /tn ZhuopinDailySnapshot /sc DAILY /st 03:00 /ru SYSTEM /rl HIGHEST /f /tr \"cmd /c \\\"C:\apps\zhuopin-recruit-agent\.venv\Scripts\python.exe C:\apps\zhuopin-recruit-agent\scripts\snapshot_data.py --data-dir C:\apps\zhuopin-recruit-agent\data --backup-root C:\apps\backups --keep 14 ^> C:\apps\backups\snapshot-last.log 2^>^&1\\\"\""
```

⚠️ `^>` 与 `2^>^&1` 的 `^` 必须有（2026-09-17 `0917BB` 实证）：远端 sshd 把整串交给 cmd.exe，`\"…\"` 在 cmd 的引号计数下是**闭合**的，裸 `>` 会被当成 ssh 这条命令自己的重定向剥掉——任务能建成（`CREATE_EXIT=0`）但 `要运行的任务` 里没有日志重定向，`snapshot-last.log` 永远不更新。建完必须用 `schtasks /query /tn ZhuopinDailySnapshot /v /fo LIST` 看 `要运行的任务`（中文系统标签是中文，`findstr "Task To Run"` 匹配不到）确认含 `> C:\apps\backups\snapshot-last.log 2>&1`。

**3. 立即触发一次并验收**（`timeout /t` 在 ssh 非控制台管道里不生效、`findstr` 英文标签在中文系统匹配不到：实际做法是 `schtasks /run` 后本机 `sleep 15`，再单独 `schtasks /query … /fo LIST` 看中文标签 `上次结果`）：

```
ssh zp51 "schtasks /run /tn ZhuopinDailySnapshot & timeout /t 10 /nobreak >nul & schtasks /query /tn ZhuopinDailySnapshot /v /fo LIST | findstr /c:\"Last Result\" /c:\"Last Run Time\" /c:\"Next Run Time\" & type C:\apps\backups\snapshot-last.log & dir /b /ad C:\apps\backups"
```

验收三条全过才算装好：
1. `Last Result: 0`
2. `snapshot-last.log` 末行 `[snapshot] 完成`
3. `dir /b /ad C:\apps\backups` 里出现今日 `daily-<yyyyMMdd-HHmm>` 目录，且用 `.venv` python 打开它的 `demo.db` 做 `PRAGMA integrity_check` = ok：

```
ssh zp51 "for /f %d in ('dir /b /ad /o-n C:\apps\backups\daily-*') do @(C:\apps\zhuopin-recruit-agent\.venv\Scripts\python.exe -c \"import sqlite3,sys;print(sqlite3.connect(r'C:\apps\backups\%d\demo.db').execute('PRAGMA integrity_check').fetchone()[0])\" & goto :done) & :done"
```

## 三、回滚

```
ssh zp51 "schtasks /delete /tn ZhuopinDailySnapshot /f"
```

不影响服务 `ZhuopinRecruitAgent`；已生成的 `daily-*` 目录留着不删（它们就是备份）。脚本文件留在 `scripts\` 无害（无人调用即惰性）。
