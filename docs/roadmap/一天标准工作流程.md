> 2026-09-20 重写（v1 为 09-17 定稿，已过期）。全景推进依据：`docs/roadmap/任务驱动上线路线图.md`。
> 口径：**场景任务驱动全自动**——每个场景从 intent 到上线是一个自转循环，有任务就自动开；**只在五道在环闸门与「等外部信息」两处停**。你不决定「下一步做什么」，只答闸门。

## 一、机器怎么自转（你不用管，知道即可）

```
需求来源 ─┬─ 你在本线提出／答闸门
          └─ 专员回件（企微）→ 值守服务归档入队 → 回件桥打标 → 无头拆件会话按章程回灌结论
   ↓
intent（grill skill 追问收敛）──G1 定稿──▶ propose（包：proposal/design/specs/tasks）
   ↓                                          └──G2 定稿──▶ plan（逐单元）
   ↓                                                          ↓
调度器（launchd，事件唤醒 + 每日 09:00 兜底）：刷新任务台账 → 算就绪集（依赖已完成、闸门已放行、
触碰区不撞车）→ 按「人事部可见优先 > M0>M1>M2>M3 > 阶段先后」排序 → 写无头块、登号池、dry-run
   → 发车（run-lanes，最多 3 条并行）→ 泳道 TDD 建造 → final review → ff 合 main → 回勾 tasks
   ↓                                                                     ↓
发布 ──G3「发」──▶ Mac 无头会话 SSH 到 .51：快照 → 依赖 → sync → 起服验证 → 冒烟，不过即回滚
   ↓
验收跟进信 ──G4「审核通过·发」──▶ 动作通道发出 → 专员回件 → 拆件回灌 → 口径 ──G5「签」──▶ 台账签认
   ↓
新需求／新场景 ⇒ 回到 intent
```

**五道闸门（唯一停点，放行只认定夺队列该行「状态＝已答」且答复为放行字）**

| 闸 | 什么时候到闸 | 你回什么 |
|---|---|---|
| G1 | 场景 intent 收敛完、无未答题 | 定 |
| G2 | 包 validate 过、无 Open Questions | 定 |
| G3 | 场景全部单元合 main，要上 `.51` | 发 |
| G4 | 跟进信 md＋docx 起草完、自检过 | 审核通过·发 |
| G5 | 回件拆件判为口径点 | 签 |

⛔ 无头会话不得越闸、不得自改台账放行；⛔ 调度器永不发信、永不发版。

## 二、你的一天

| 时段 | 你做什么 | 系统在做什么 |
|---|---|---|
| **上班到位** | 任一设备打开本 Cowork 线，说「看看泳道」；把闸门一行答完 | 夜间事件已处理完；09:00 日历兜底唤醒调度器；跟进信超期与观察窗到期自检 |
| **白天** | 不用守。只有异常才会有机器人私信；收到就回本线说「看看泳道」 | 泳道收尾 ⇒ 开下一批；你的答复提交 ⇒ 产生事件 ⇒ 按答复继续开；专员回件 ⇒ 自动归档拆件回灌（不打扰你） |
| **新场景** | 说「XX 场景跑 grill」，逐题答（15 分钟无答复的题按推荐生效，无默认项必答） | `requirement-grill` skill 自查可查事实、只问真需你定的；产出 intent 停 G1 |
| **要专员出信息** | 说「给 XX 写跟进信」，审稿回「审核通过·发」 | 我起草 md＋docx，经动作通道发出；回件自动拆件，口径进台账，需签的进队列 |
| **上线** | 队列出现「G3 发布 XX」，回「发」 | Mac 常驻内网，无头会话 SSH 到 `.51` 按发版清单执行，不过即回滚；发完在本线报结果 |
| **下班前**（可选） | 说「看看泳道」，清掉当天剩余闸门 | 答复一提交就触发调度，夜里继续跑 |

**「看看泳道」我做的五步**：① 读真身（泳道结果、合入、调度器日志、值守状态）② 报待答闸门（选项、代价、推荐、一行可粘答复）③ 只报异常（PARTIAL/FAIL、服务断连、判为待人的拆件）④ 收答复写回队列并提交 ⑤ 调度器若没跑，我在本线直接编排发车并登记原因。

## 三、什么时候会停下等你

- **五道闸门**（上表）；
- **等外部信息**：专员回件、真实文件帧、`.env` 里的 key 与 webhook、`.51` 现场动作；
- **不可代项**：预算与采购（如语音主机）、合规签认、真实简历入库闸、候选人对外通道。

以上都进 `docs/roadmap/定夺队列.md`。其余任何「下一步做什么」都不该等你——发现它在等你，说明机制有缺口，我登记并修。

## 四、你不需要再做的事

- 不开终端、不粘命令（发信、装服务、提交文档、发版都走通道；三类例外仍由你本人：对外发送、合规与人工门禁、`.51` 现场动作）
- 不盯泳道、不决定下一批（调度器按台账能开尽开，并发上限 3）
- 不看正常完成的通知（全 OK 不私信，拆件完成不私信）

## 五、在哪台设备上做

**iPad／手机远程本线即可**：看看泳道、答闸门、审信回「发」、`.51` 发版与运维（G3 放行后由 Mac 无头任务执行）。
**前提**：Mac 不睡眠、Claude 桌面 App 常开、Mac 在内网（发版前先测可达，不通即停）。
**仍需回 Mac 或现场**：① 写 key／webhook 进 `.env` ② Mac 上的授权弹窗 ③ `.51` 整机重启起不来需物理控制台 ④ 门户导航 HTML 在 Win 笔记本改。

## 换道提醒（Shao Peishen 2026-09-18 定，Cowork 侧自检）

Cowork 主动提醒他换新线，⛔ 不等他问、⛔ 不提额度也不制造焦虑——只说时机。

**任一条命中即在当轮回复末尾加一行提醒**：
- 本线已跨过一个完整阶段（如一次 `.51` 发版收口、一批定夺答完、一份对外文件发出）；
- 单线往返已超过约 50 轮，或已连续用了半天以上；
- 本线出现过一次上下文压缩，或我判断下一步要读大文件／看图，历史已明显偏长。

**提醒里只给三样**：一句「建议换道」＋接力文件已更新到哪一节＋可直接粘的开场词（`docs/session接力.md`「开场词（复制即用）」节，编号现查号池台账）。
**换道前 Cowork 必做**：把接力文件顶部那节刷成当下真身（机制、各场景状态、下一步、在途泳道与待答定夺），提交推送后再给开场词。
**不受影响的**：调度器、泳道、值守服务、定时任务都在 Mac 上自跑，换道不打断；预授权的闸门（如 G3 条件式放行）仍然有效。
