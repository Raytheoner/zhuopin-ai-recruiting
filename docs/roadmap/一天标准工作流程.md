# Shao Peishen · HR 项目一天标准工作流程

> 2026-09-17 定稿（Cowork·HR业务线-接力0917D）。前提：任务驱动自转（`docs/roadmap/任务驱动workflow设计.md`）——有任务就自动开，**只在「需你定夺」和「等外部信息」两处停**。你不需要决定下一步做什么，只需要答定夺。

## 一句话口令

在本 Cowork 线里说 **「看看泳道」**，我按下面「开机五步」跑一遍并汇报。不说也不影响自转，只是你看不到定夺积压。

## 开机五步（你说「看看泳道」后我做的事）

1. **读真身**：泳道批次结果、合入 main 情况、值守服务状态、调度器最近一次运行日志。
2. **报定夺队列**（`docs/roadmap/定夺队列.md`）：只列待答项，每项带选项、代价、推荐，末尾给 `1a，2b…` 一行答复模板。
3. **报异常**：泳道 PARTIAL/FAIL、服务断连、回件拆件判为「待人」的项。全 OK 的批次不报。
4. **收你的答复**：写回定夺队列并提交 ⇒ 自动产生事件 ⇒ 调度器按答复继续开任务。
5. **兜底发车**：调度器若未安装或未运行，由我在本线直接编排发车，并登记原因。

## 一天的节奏

| 时段 | 你做什么 | 系统在做什么 |
|---|---|---|
| **上班到位** | 回 Mac（或手机上本线），说「看看泳道」；把定夺一行答完 | 夜间与清晨的事件已被调度器处理；09:00 日历兜底唤醒调度器、tick 检查跟进信超期与观察窗到期 |
| **白天工作中** | 不用守。收到机器人私信（只在泳道异常时才有）就回本线说「看看泳道」 | 调度器被事件唤醒：泳道收尾 ⇒ 开下一批；你的答复提交 ⇒ 按答复开任务；专员回件 ⇒ 自动归档、拆件、回灌（不打扰你） |
| **有新需求/新场景** | 在本线说「XX 场景跑 grill」，逐题答 | 我按需求收敛方法出设计树与选择题；你答完 ⇒ intent 落档 ⇒ 调度器接手 propose → plan → 建造 |
| **需要专员给信息** | 在本线说「给 XX 写跟进信」，审稿回「发」 | 我起草 md+docx；你回「发」后经动作通道直接发出（不用开终端）；回件到达自动拆件，结论与口径进台账，需签认的进定夺队列 |
| **发布到 `.51`** | 定夺队列里出现「发布 XX」，回「发」 | 目前仍需你拍板；执行动作通道化排在 R1–R5 之后 |
| **下班前**（可选） | 说「看看泳道」，把当天剩余定夺答完 | 答复一提交就触发调度，夜间可继续跑能开的任务 |

## 什么时候会停下等你

- **需你定夺**：需求取舍、口径签认、发布 `.51`、跟进信「发」、预算/采购（如模型 API key）、不可代项（合规、候选人对外通道）。
- **等外部信息**：专员回件（如人事部#2 的岗位清单）、真实文件帧（TD-51）、群 webhook 等凭据由你配置。
- 以上都进定夺队列；其余任何「下一步做什么」都不该等你——如果发现它在等你，说明机制有缺口，我登记并修。

## 你不需要再做的事

- 不开终端、不粘贴命令（发信、重启服务、安装 LaunchAgent、提交文档都走通道）
- 不盯泳道、不决定下一批（调度器按任务台账能开尽开）
- 不看正常完成的通知（全 OK 不私信；拆件完成不私信）

## 两处说明

- 「看看泳道」是**查看＋收答复**，不是「启动总线」：调度器装好后由事件自己转，你不说它也在跑。本线只在你说话时活着，所以定夺积压要靠你来看。
- 需求收敛（grill）：HR 仓库里还没有独立的 grill skill，目前用 `zhuopin-requirement-grill` 的方法在本线进行（M2 十题就是这样收敛的）。已作为一条任务进台账：把它移植成 HR 仓库的 `requirement-grill` skill，让 intent 这一棒也有固定规则。
