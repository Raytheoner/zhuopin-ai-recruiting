# S-Offer Offer 生成 · intent（需求收敛结论 · 首轮备料）

> 来源：本文件「设计树与前沿」第 1 轮（备料），**尚未答题**。Shao Peishen 在本线答 `Q1a，…` 后由 Cowork 转写进「决策」并清「待答题」。本文件是 `openspec propose` 的输入。依据文档：`02-系统架构与MVP范围.md` §2.1–2.2、§3「明确不在 MVP 内」、§6；`01-开源调研与技术选型.md` §2.7；`CLAUDE.md` 合规红线／决策代理；`openspec/specs/outbound-approval-gate/spec.md`；`docs/tech-debt.md` TD-8／TD-JD-2；`docs/roadmap/M2-intent.md` D6 与立包后裁决 Q5。
> ⛔ 本稿不是 spec，不是现状描述。

## 目标
面试通过 → HR 在工作台选择候选人与岗位 → 系统按模板生成 Offer 文书草稿（带 AI 生成标识）→ 内部审批（业务经理／决策人留痕）→ HR 导出 docx 发给候选人 → 回填候选人答复 → `application.status=hired` 或回退。使用者：HR（发起、导出、回填）、审批人（业务经理／总经理）。

## M2 已自查的事实
- 范围定性：Offer 生成「明确不在 MVP 内」，集成活，主链路验证后再接；路线图波次 5（来源：`02` §3；`docs/roadmap/任务驱动上线路线图.md` 波次 5）。
- 外发门禁只登记了 `rejection_letter` 与 `interview_invitation` 两类；**未登记的消息类型一律拦截**（fail-closed），⛔ 不得绕过 `deliver_candidate_message()`；`CANDIDATE_OUTBOUND_ENABLED` 默认关、生产无调用方（来源：`openspec/specs/outbound-approval-gate/spec.md`「门禁覆盖范围」「fail-closed」；TD-8）。⇒ Offer 若走系统外发，须新增登记类型（如 `offer_letter`）。
- AI 生成的 JD、拒信、邀约须带标识（《AI 生成合成内容标识办法》2025-09-01 施行）；「标记为人工撰写」留痕先例在 TD-JD-2（来源：`CLAUDE.md` 合规红线；`docs/tech-debt.md` TD-JD-2）。
- 数据模型：`stage.stage_type` 含 `offer`／`hired`；`application.status ∈ {ongoing, hired, refused}`；流转写 `application_stage_history`（来源：`02` §2.1）。
- 淘汰口径：AI 只排序不淘汰，淘汰由 HR 在工作台批量确认并留痕；`rejection_record.reason_type='ai_score'` 恒 0；拒信生成尚无调用方（来源：`docs/roadmap/M2-intent.md` D6；TD-8）。
- 企微审批 API 免费，但按钮式审批须自建应用 `template_card`＋公网 HTTPS 回调，`.51` 无公网（来源：`01` §2.7；`04` §1）。
- 候选人联系方式：M2 Q5 手机号哈希、明文不落库（与 S-排期 Q2 同一冲突，⛔ 本场景不重问，等 S-排期 Q2 结论）（来源：`docs/roadmap/M2-intent.md` 立包后裁决）。
- 不可代：候选人对外通道（拒信／邀约对外发送）；预算与外部采购（来源：`CLAUDE.md` 决策代理）。
- HR 现状：Excel ＋ 微信/邮件；年招几十到百人（来源：`01` §2.6）。

## 决策（已从事实源自答，依据逐条列出；G1 时可逐条改）
- **D1 定位**：集成活；波次 5，顺序在 S-排期之后、S-入职之前（Offer 接受是入职入口）。依据：`02` §3；路线图波次 5。
- **D2 Offer 外发必经门禁，且须新增登记类型**：系统若对候选人发送 Offer，必须先在门禁类型清单登记 `offer_letter`（高风险、需人工确认），走 `deliver_candidate_message()`；未登记即被拦。依据：`outbound-approval-gate` spec；TD-8。
- **D3 AI 生成标识**：Offer／拒信文书由模型生成或润色即带标识；人工改写后按 TD-JD-2 形态留「人工撰写」痕。依据：`CLAUDE.md` 合规红线；TD-JD-2。
- **D4 AI 不做录用决定**：系统只生成文书与流转，录用与薪资由人定并留痕（`human_review`／审批记录）。依据：`CLAUDE.md` 合规红线；`02` §2.2。
- **D5 状态落流转事实表**：`stage_type=offer→hired`，`application.status=hired`；拒绝 Offer 回 `ongoing` 或 `refused` 并写 history。依据：`02` §2.1。
- **D6 审批载体**：Web 工作台审批（留痕），⛔ 不做企微卡片审批（无公网回调、aibot 被动）。依据：`01` §2.7；`04` §1；M2 D8 同理。
- **D7 联系方式口径不重问**：沿 S-排期 Q2 结论。依据：M2 Q5。

## 设计树与前沿（第 1 轮）

```
S-Offer
├─ A 范围档：文书生成 / +内部审批 / +对候选人发送与签收                      ← Q1
│   └─ A1 电子签采购（取决于 Q1c）                                          → 外部依赖
├─ B 敏感字段（薪资等）是否入库                                             ← Q2
├─ C 拒信是否并入本场景（共用门禁与模板引擎）                               ← Q3
├─ D 候选人答复回收：人工回填 / 一次性链接自助答复                           ← Q4
├─ E 审批链（谁签、几级）＝现用规则（专员）                                  → 待专员
├─ F Offer 模板与拒信话术样例（专员）                                        → 待专员
└─ G 联系方式口径                                                          ✅ D7（随 S-排期 Q2）
```

## 建议交付单元（propose 时细化）
U1 Offer 域模型（`offer` 记录挂 `application`：模板版本、字段、审批状态、答复；敏感字段按 Q2）→ U2 模板引擎＋文书生成（AI 标识、docx 导出，复用 M1 JD 生成的标识机制）→ U3 内部审批流（工作台、留痕）→ U4 门禁类型登记 `offer_letter`（＋若 Q3a 则拒信 `rejection_letter` 接线）→ U5 答复回填与流转（hired／refused）。

## 不做
AI 决定薪资或录用；企微卡片审批；自动对外发送（开关默认关，开启不可代）；电子签（一期，视 Q1）；候选人自助答复入口（一期，视 Q4）。

## 不可代项（进 tasks 时标注）
候选人对外通道（Offer／拒信发送）；薪资等敏感字段入库口径（若 Q2b，改 PIA）；电子签／短信等采购；`.51` 发版。

## 待答题
- [ ] **Q1 · 范围档**：
  (a) **文书生成**：模板＋岗位＋候选人字段生成 Offer 文本（带 AI 标识），HR 导出 docx 自行发送——代价：审批与发送仍在系统外。
  (b) **(a) ＋ 内部审批流**：业务经理／决策人在工作台审批、留痕后才可导出——代价：审批人多一个登录动作（需登录就位）。
  (c) **(b) ＋ 对候选人发送与签收**：经门禁外发、候选人一次性链接确认／电子签——代价：对外通道（不可代）＋电子签采购。
  ➡️ **推荐**：(b)。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (b) 执行。
- [ ] **Q2 · 薪资等敏感字段是否入库**：
  (a) **不入库**：系统只留岗位／部门／入职日期／汇报对象，薪资由 HR 在导出 docx 后手填——代价：审批看不到薪资，审批只对「录用」不对「待遇」。
  (b) **入库**（字段级加密＋访问留痕＋留存策略）以支持审批与后续入职——代价：PIA／合规验收 #1 范围扩大，权限模型要区分「可见薪资」角色。
  ➡️ **推荐**：(a) 一期。
  ⏸️ **本项无默认，须你明确答复**（合规口径／数据范围）。
- [ ] **Q3 · 拒信是否并入本场景**：M2 D6 定淘汰由 HR 确认，拒信生成至今无调用方（TD-8）。
  (a) **并入**：拒信／Offer 共用「候选人文书」模板引擎与门禁接线，一个单元做完——代价：本场景范围变大，但 TD-8 一次还清。
  (b) **不并入**：拒信留给 M2 后续单元——代价：门禁接线分两次做，观察期两次起算。
  ➡️ **推荐**：(a)。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (a) 执行。
- [ ] **Q4 · 候选人答复回收**：
  (a) **HR 人工回填**（接受／拒绝／谈判中）——代价：多一步录入。
  (b) **一次性链接自助答复**——代价：对外通道（不可代）＋候选人端页面。
  ➡️ **推荐**：(a) 一期。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (a) 执行。
