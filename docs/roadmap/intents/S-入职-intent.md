# S-入职 入职流程 · intent（需求收敛结论 · 首轮备料）

> 来源：本文件「设计树与前沿」第 1 轮（备料），**尚未答题**。Shao Peishen 在本线答 `Q1a，…` 后由 Cowork 转写进「决策」并清「待答题」。本文件是 `openspec propose` 的输入。依据文档：`02-系统架构与MVP范围.md` §1 L0、§2.1、§3「明确不在 MVP 内」、§6；`01-开源调研与技术选型.md` §2.7；`CLAUDE.md` 合规红线／部署约束／决策代理；`.claude/skills/liaison-unpack/SKILL.md` §〇 ⑨；`docs/tech-debt.md` TD-11；`docs/roadmap/任务驱动上线路线图.md` 波次 5。
> ⛔ 本稿不是 spec，不是现状描述。

## 目标
Offer 接受（`application.status=hired`）→ 系统生成该岗位／部门的入职清单（合同、材料、体检、设备、账号、带教人）→ HR 与用人部门在工作台逐项勾选、看进度 → 入职日完成写 `application_stage_history` 终态。使用者：HR（主）、用人部门经理（看本部门进度）。

## M2 已自查的事实
- 范围定性：入职流程「明确不在 MVP 内」，集成活；路线图波次 5（来源：`02` §3；路线图波次 5）。
- L0 外部系统只列企业微信、日历、（二期）渠道；**没有** HRIS／ERP／考勤对接的既定决策（来源：`02` §1）。企业AI转型仓库有 ERP／SRM 对接经验，只读参考、⛔ 不拷贝（来源：`CLAUDE.md`「企业AI转型」节）。
- 敏感个人信息：入职材料含身份证、银行卡、社保等；合规清单要求「敏感信息独立勾选」同意；候选人个人信息不得进值守归档／无头会话 prompt（红线 ⑨）（来源：`02` §6；`.claude/skills/liaison-unpack/SKILL.md` §〇 ⑨）。
- 企微通讯录接口 2022-06-20 后不返回手机/邮箱（来源：`01` §2.7）；入职建号若走企微 API 需自建应用（同 S-排期）。
- 禁止人脸识别（入职人脸打卡／人脸建档类一律不做）（来源：`CLAUDE.md` 合规红线）。
- 定时基础设施缺失（TD-11）——入职提醒（入职前 N 天、材料缺失）同受限。
- 数据模型：`stage_type=hired` 为终态之一；`application` 独立于 `candidate`（来源：`02` §2.1；`CLAUDE.md` 数据模型要点）。
- 留存策略属合规验收 #1（PIA＋同意条款＋留存策略），法务签认在途（X3）（来源：路线图 §二 X3；M2 D2）。
- 鉴权：无正式鉴权；处理真实个人信息前须登录＋留痕（来源：`04` §1；`CLAUDE.md` 部署约束 5）。
- 公司规模约 300 人、年招几十到百人（来源：`CLAUDE.md` 首段；`01` §2.6）。

## 决策（已从事实源自答，依据逐条列出；G1 时可逐条改）
- **D1 定位**：集成活；波次 5，顺序在 S-Offer 之后（Offer 接受是入口）。依据：`02` §3；路线图波次 5。
- **D2 状态终态**：入职完成＝`application.status=hired`＋`stage_type=hired`，写 history；候选人转员工后的员工档案**不由本系统承担**（L0 无 HRIS 决策）。依据：`02` §1、§2.1。
- **D3 不做人脸**：入职环节不引入任何人脸采集（打卡／建档）。依据：`CLAUDE.md` 合规红线。
- **D4 个人信息不经值守通道**：入职材料一律不经 aibot／私信收集，不进无头会话 prompt。依据：红线 ⑨；M2 D1 同一口径。
- **D5 提醒与 TD-11 同批**：入职提醒若纳入，随定时基础设施一起建。依据：TD-11。
- **D6 门槛**：登录＋访问留痕就位后才处理真实入职者信息。依据：`CLAUDE.md` 部署约束 5。
- **D7 入职文书若 AI 生成带标识**。依据：`CLAUDE.md` 合规红线（JD／拒信／邀约类推）。

## 建议交付单元（propose 时细化）
U1 入职域模型（`onboarding_checklist` 模板按岗位／部门；条目状态挂 `application`）→ U2 工作台页（清单生成、勾选、进度视图；部门经理只读视 Q2）→ U3 完成流转与终态 →（可选）U4 提醒节点（随 TD-11）→（可选，视 Q1）U5 材料收集或系统对接。

## 不做
员工档案／HRIS；人脸类任何功能；材料经值守通道收集；企微卡片；自动外发。

## 不可代项（进 tasks 时标注）
敏感材料入库口径（若 Q1b，改 PIA／合规验收 #1）；入职后数据留存／删除口径（法务）；企微自建应用／ERP 对接账号；新员工自助入口（对外通道）；`.51` 发版。

- [ ] **Q1 · 范围档**：
  (a) **清单跟踪**：按岗位／部门生成入职待办清单，HR 勾选与看进度；材料本身不入库——代价：材料仍在 HR 系统外（纸质／Excel）。
  (b) **(a) ＋ 材料收集**：新员工经一次性链接上传身份证／学历／银行卡等——代价：敏感个人信息入库，PIA／同意条款／留存策略全部扩范围，且对外通道（不可代）。
  (c) **(b) ＋ 现有系统对接**（企微建号、考勤、ERP）——代价：自建应用与对接账号（不可代），集成工作量最大。
  ➡️ **推荐**：(a) 一期。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (a) 执行（(b)(c) 涉合规与对外通道，⛔ 不作默认）。
- [ ] **Q2 · 使用者范围**：
  (a) **仅 HR**——代价：用人部门看不到进度，仍靠微信问。
  (b) **HR ＋ 用人部门经理只读**（本部门）——代价：经理需登录（登录就位后零成本）。
  (c) **(b) ＋ 新员工本人自助**（一次性链接看清单／上传）——代价：对外通道（不可代）。
  ➡️ **推荐**：(b)。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (b) 执行。
- [ ] **Q3 · 入职后候选人招聘数据的处置**：

  (b) **保留**（作为人才库与内部转岗依据）——代价：合规验收 #1 留存策略须明确写入并取得同意。
  ➡️ **推荐**：(a)，具体期限随合规验收 #1 留存策略（法务）。
  ⏸️ **本项无默认，须你明确答复**（合规口径；与法务结论联动）。
- [ ] **Q4 · 提醒机制一期是否要**：

  (b) **要**：入职前 3 天／材料缺失提醒——代价：必须先建定时基础设施（TD-11，同时还 M1 5.6/6.8），本场景工期＋。
  ➡️ **推荐**：(a) 一期；TD-11 另立包时再接。
  ⏸️ **默认项**：15 分钟内无答复 ⇒ 按 (a) 执行。
