# [Mac]0920L 提交通道白名单纳入技能文件（并提交 0920R 的滞留改动）

## 零、为什么

Cowork 在隔离 VM 里碰不得 git，文档提交走 `scripts/commit_request.py` 请求通道。但该通道白名单只收
`docs/**` 与 `openspec/changes/<名>/tasks.md`：`0920R` 改完 `.claude/skills/lane-watch-relay/SKILL.md`
（补「判据可用性」表——`pgrep`／`.51` 探针两条判据在挂载侧失效）提交即被拒
（`.claude/handoff/commit/20260920-074535-0920R.rejected`，reason 原文「不在白名单…内」），
改动**滞留主工作区未提交**，正是 `0917K` 那类会挡住 ff 合并的状态。

不修的代价：Cowork 每改一次技能就要起一条泳道来提交，一条泳道换一次 `git add`，与收益不成比例；
而滞留态不报错，下一条泳道 ff 合并时才炸。

## 一、开工自核（任一不过即顶格 `OPENER_PARTIAL` 并停）

1. `git rev-parse --abbrev-ref HEAD` ＝ `main`。
2. 🔴 **本条 `worktree ❌`，必须在仓库根主工作区跑**。理由写死：要提交的是**主工作区里的未提交改动**，
   worktree 是另一份检出，看不见它（口径：提交 main 上的未提交改动必须取消 worktree 勾选）。
   ⛔ 不许自建 worktree「以求隔离」——那会让动作①永远提交不到东西还报成功。
3. `git status --porcelain .claude/skills/lane-watch-relay/SKILL.md` 非空。
   若为空 ⇒ 说明已被别人提交，**跳过动作①，继续②③**，并在收工报告里写明。

## 二、动作

① **提交滞留改动**：`git add .claude/skills/lane-watch-relay/SKILL.md`，
   commit message：`docs(0920R): lane-watch-relay 补判据可用性表（pgrep／.51 探针在挂载侧失效）`。
   ⛔ 不要 `git add -A`／`git add .`——工作区可能有别的在途东西。

② **改白名单**：在 `scripts/commit_request.py` 的路径校验里新增一条规则，只收
   `.claude/skills/<名>/SKILL.md`，`<名>` 限 `[A-Za-z0-9_-]+`（不含 `/`、不含 `..`）。
   🔴 **⛔ 绝不放开整个 `.claude/**`**：`.claude/settings.json` 是安全配置（只能 Shao Peishen 手工改）、
   `.claude/hooks/*.py` 是护栏、`.claude/handoff/**` 是通道自身的请求目录，三者必须仍然被拒。

③ **补测试** `tests/test_commit_request_whitelist.py`，四条断言：
   `docs/x.md` 放行；`.claude/skills/lane-watch-relay/SKILL.md` 放行；
   `.claude/settings.json` 拒；`.claude/skills/x/hooks.py` 拒。
   🔴 测试必须 **import `scripts/commit_request.py` 里那个真正的校验函数**（自己去读它的真名），
   ⛔ 不许在测试里另写一份等价实现——那样白名单改坏了测试也不会红。

④ **narrow 跑**：`venv/bin/python -m pytest tests/test_commit_request_whitelist.py -q`。
   ⛔ 不跑全量 pytest（口径：回归闸只跑受影响的测试类）。

⑤ 提交 ②③ 并 `push`。
