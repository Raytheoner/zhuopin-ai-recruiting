## 零、为什么（根因，已实证）

2026-09-18 Cowork·`0918G` 实核：远端文件工具对 `.claude/**` **只读**——`device_list_dir` 可以列、`device_commit_files` 写被直接拒，错误原文 `Writing to .claude is not permitted via remote tools.`。这不是缺了 `device_bash` 才有的问题：`.claude/` 是 Claude 自身数据目录，受限会话一律写不进去。而三条通道（提交 `.claude/handoff/commit/`、发车 `.claude/handoff/launch/`、事件 `.claude/handoff/events/`）的投递口全在 `.claude/` 下 ⇒ **只要会话没有本机 shell，就一件也投不进来**，只能靠 Shao Peishen 手工粘贴破局。本条把投递口搬到仓库根，一次性根治。

## 二、`scripts/handoff_relay.py`（在 worktree 内做）

🔴 **路径解析**：仓库根一律用 `Path(__file__).resolve().parents[1]` 取（脚本自身位置的上一级），⛔ 不用 `os.getcwd()`、⛔ 不用 `git rev-parse --show-toplevel`——后者在 worktree 里会解析到 worktree，装成 launchd 任务后必须指向**主检出**。

扫仓库根 `handoff-inbox/` 顶层文件，按**文件名前缀**分派，合格者 `os.replace` 到目标目录、**去掉前缀**后沿用各通道既有命名：

| 投递件名 | 落点 | 落点文件名 |
|---|---|---|
| `commit-<ts>[-<来源>].request` | `.claude/handoff/commit/` | `<ts>[-<来源>].request` |
| `commit-<ts>[-<来源>].action` | `.claude/handoff/commit/` | `<ts>[-<来源>].action` |
| `launch-<ts>[-<来源>].request` | `.claude/handoff/launch/` | `<ts>[-<来源>].request` |
| `event-<事件名>` | `.claude/handoff/events/` | `<事件名>` |

搬运前逐条校验，任一条不过即移入 `handoff-inbox/rejected/` 并往 `handoff-inbox/relay.log` 追加一行（时间、原文件名、拒收原因）：

1. `<ts>` 形如 `YYYYmmdd-HHMMSS`；`<事件名>` 只含 `[A-Za-z0-9_.-]`；⛔ 文件名含 `/`、`..`、绝对路径一律拒。
2. 文件 mtime 距今 < 30 秒 ⇒ 本轮跳过不搬（防半截文件），下一轮再看。
3. `.request`／`.action`（commit 类）：内容 JSON 可解析；`paths` 全部落在提交通道既有白名单内（`docs/**`、`openspec/changes/*/tasks.md`）；⛔ 白名单判据从现有提交通道脚本里**复用同一份实现**，不要另写一套。
4. 发车件：整行必须匹配 `^--full-auto --yes --only [0-9A-Za-z]+(,[0-9A-Za-z]+)*$`。⛔ 这一条是安全闸——发车参数会被 shell 执行，除该白名单外的任何字符（分号、反引号、`$(`、重定向、额外参数）一律拒收，不得放宽。
5. 事件件：必须为 0 字节。

**红线：中继只搬运、不放行。** ⛔ 不解析 G1–G5、不改 `docs/roadmap/任务台账.yaml` 状态、不碰 `docs/roadmap/定夺队列.md`；`send-followup` 的双闸校验仍在原动作通道里做，中继不得绕过、不得代答、不得改写文件内容（只改文件名与位置）。
