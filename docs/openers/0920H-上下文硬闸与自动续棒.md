# [Mac]0920H 上下文硬闸 ＋ 自动续棒（提醒型守卫 → 有消费者的硬闸）

## 零、为什么

Shao Peishen 2026-09-20 带来姐妹项目（Win 端）实况：七条无头泳道上下文峰值 151k–244k，**全部越过 150k 转场线、无一条按规则收尾**。根因判定：守卫是**提醒型、没有消费者**——提醒的对象是泳道自己，而泳道正埋头干活。

本项目 `0920G` 已把峰值记进 `results.tsv` 第 13 列 `upeak`（可观测），但**触发与消费两头都还没有**：

- `scripts/hooks/context-guard.py` 只挂 `UserPromptSubmit`。无头泳道一辈子只有开场那一条 user prompt（彼时上下文≈0）⇒ 运行中**永不触发**
- 函数开头写死 `if HR_HEADLESS_LANE: return 0`，是 `0916K` 的显式豁免（当时 Win 端 #584/#585 泳道被 150k 提醒叫停、**半途收尾**）
- `run-lanes.sh` 对 `PARTIAL` 只记一行继续跑，没有「因上下文而留步 ⇒ 自动排续棒」这一路

🔴 **本条的两半不可拆**：只截断不自动续棒 ＝ 回到 `0916K` 的半途收尾；只自动续棒不截断 ＝ 没有触发点。
**必须一次做完两半才允许收口**，⛔ 不许只交付其中一半。

## 一、A 半：触发（`scripts/hooks/context-guard.py`）

1. 脚本改成按 `hook_event_name` 分流，**两个挂点共用一份代码**：
   - `UserPromptSubmit`：**行为一字不改**（含 `HR_HEADLESS_LANE` 豁免、150k/250k 两档、`/tmp/cc-context-guard-<sid>` 去重）。有人值守会话的体验必须零变化。
   - `PostToolUse`（新增）：**只对无头泳道生效**（`HR_HEADLESS_LANE` 非空才处理，为空直接 return 0——⛔ 有人值守会话不得在每次工具调用后被注入）。
2. `PostToolUse` 分支行为：读 transcript 最后一次 assistant usage，`ctx = input + cache_creation + cache_read`。
   阈值取环境变量 `HR_LANE_CONTEXT_LIMIT`，**默认 150000**。`ctx < 阈值` ⇒ return 0。
   `ctx ≥ 阈值` 且本 session 未注入过（同样用去重标记文件，档位记 `relay`）⇒ 注入下面这段，**exit 0 不阻断**：

   > 【上下文硬闸·自动注入，非用户原话】本会话上下文已约 <N>k，已越过转场线。
   > 请**把手上这一个里程碑做完并提交**（该提交的提交、该 push 的 push），然后顶格输出一行：
   > `OPENER_PARTIAL: 上下文转场 | 续棒: 分支=<分支名或-> worktree=<路径或-> 上一条commit=<hash或-> 已完成=<一句话> 待续=<一句话>`
   > ⛔ 不要开始新的里程碑、⛔ 不要缩小或放弃已开始的这一个、⛔ 不要在报告里省略「待续」。
   > 续棒由 `run-lanes.sh` 自动排，你**不需要**也**不许**自己再起 session。

3. 新增 `tests/test_context_guard.py`（若已存在则追加用例），至少钉住四条：
   ① `UserPromptSubmit` ＋ `HR_HEADLESS_LANE` 有值 ⇒ 零输出（旧豁免不变）
   ② `PostToolUse` ＋ `HR_HEADLESS_LANE` 为空 ⇒ 零输出
   ③ `PostToolUse` ＋ 无头 ＋ ctx=149_999 ⇒ 零输出；ctx=150_000 ⇒ 注入且含 `OPENER_PARTIAL: 上下文转场`
   ④ 同一 session 第二次越线 ⇒ 不重复注入
   构造假 transcript（jsonl 临时文件）＋ 假 stdin JSON 即可，⛔ 不起任何真会话。

## 二、B 半：消费者（`docs/openers/run-lanes.sh`）

1. 判状态那段（约 686–692 行）在 `PARTIAL` 之后加一层：日志哨兵行含 `上下文转场` ⇒ 状态记 **`CTX-RELAY`**（仍写进 `results.tsv` 第 3 列）。
2. `CTX-RELAY` 的处置：
   - ⛔ **不** `mark_done`（活没干完，泳道标注不许摘）
   - 从哨兵行里抓出 `分支=` `worktree=` `上一条commit=` `已完成=` `待续=` 五个字段
   - 在**同泳道队尾**追加一条续棒条，编号 `<原id>续<n>`（如 `0920H续1`），正文＝「引用原 opener 正文文件」＋「前置：分支/worktree/上一条commit 原样带上」＋「从『待续』继续，⛔ 不重做『已完成』」＋原 opener 的红线段指针
   - 续棒条跑完若又越线 ⇒ 再续，**上限 `HR_LANE_RELAY_MAX`（默认 3）**；超上限记 **`RELAY-EXHAUSTED`** 并**停本泳道**（与 FAIL 同处置），⛔ 不许无限续
3. 收工汇总必须多打一行：`🔁 本批自动续棒 N 次：<原id> → <续1> → …`；一条都没有时打 `🔁 本批无上下文续棒`。
4. 续棒条**不进号池台账**（它是运行态派生，不是人派的 opener），但**必须进 `results.tsv`** 各占一行，`upeak` 照记。
5. 新增/追加 `tests/test_run_lanes_relay.py`：用**假日志文件**喂解析函数，钉住
   ① 含 `上下文转场` 的 PARTIAL ⇒ `CTX-RELAY` 且抓齐五字段
   ② 普通 PARTIAL ⇒ 仍是 `PARTIAL`、不触发续棒
   ③ 第 4 次越线 ⇒ `RELAY-EXHAUSTED` 且本泳道后续条不跑
   ⛔ 不为验证起真泳道。
