## 二、交付物

1. **后端**：`GET /api/resumes/{resume_id}/parsed` 响应新增一个**只读**键
   `field_review_status`：形如 `{"expected_city": "pending", ...}`——按字段给出最近一条
   `field_review_queue` 行的 `status`（`pending` / `reviewed`）；没有记录的字段不出现在这个 map 里。
   - 复用现有 `_latest_field_review_rows(resume_id)` 的实现思路（列表接口已经在用它算
     `pending_review_count`，⛔ 不要再写第二份取最新行的 SQL）。
   - `parsed_json` 原样返回，⛔ 不要往里塞东西（存储不动、响应兼容）。
2. **前端**：`resume_review.html` 的 `loadParsed()` 改为
   `parsedFields[name] = { ...field, review_pending: body.field_review_status?.[name] === "pending" }`；
   其它渲染逻辑（黄底、徽标、确认/修改流程）⛔ 不改。
3. **测试**：新增 `tests/test_resume_review_pending.py`：
   - 造一条 `field_review_queue` pending 行 + 一条 reviewed 行 ⇒ 调 `/parsed` 断言 map 内容正确；
   - 无任何 review 行 ⇒ `field_review_status` 为空 `{}`（或等价），且 `parsed_json` 与库中逐字一致；
   - 页面 HTML 断言：`field_review_status` 字面量出现在 `resume_review.html` 里（防接线被回退）。
4. **登记**：在 `docs/tech-debt.md` 的 TD 行或 findings R-1 处补一行"已由 1001H 闭环"的指针
