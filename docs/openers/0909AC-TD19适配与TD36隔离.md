## 二、TD-19：写适配

**已知的形状**（来自 findings「遗留发现」，⛔ 不要重新调研）：

- `WSClient.connect` 是 `async def connect(self) -> "WSClient"`，建连成功后**立即返回**，
  不阻塞。同步调用它只得到一个协程对象，不发生任何网络动作
- 真正阻塞到进程被打断的是 `run(self) -> None`（等价于 `new_event_loop()` +
  `run_until_complete(self.connect())` + `loop.run_forever()`）
- 连接生命周期事件名是硬编码字面量 `connected` / `disconnected`（源码 `_setup_ws_events()`），
  **不是** `aibot.EventType`（那是消息内容类型枚举，与连接无关）

**要交付的**：`session_client.run_forever` 拿到的那个 callable 必须真正「阻塞到断开为止」。

🔴 **不许用"让它先跑起来"的方式绕过护栏**：`make_sdk_connect` 的表面校验（探到协程函数就
`raise SdkSurfaceUnverifiedError`）是这条链**唯一**的护栏，它防的正是「服务起得来、日志正常、
但从不真正建连」这类**静默**故障。你可以**修改**这道校验让它认新的正确形状（本 opener 即为
Shao Peishen 对改 `REQUIRED_CLIENT_ATTRS` / `EVENT_*` / 校验逻辑的授权），但：

- ⛔ 不许**删掉**校验、不许把它降级成 warning、不许加"跳过校验"的开关或环境变量
- ✅ 改完后，「表面对不上就拒绝启动」这个性质必须仍然成立——用一个 Fake（其 `run` 形状不
  合契约）驱动，断言仍然拒启动。这条断言是你没有偷偷拆掉护栏的证据

⚠️ **线程归属**：`client.run()` 自己建事件循环。第 7 章的接线是「值守线程独占库、主线程跑
连接」（`19dd6dd`），⛔ 不要把它挪到子线程里去，也不要在已有事件循环里调它。
