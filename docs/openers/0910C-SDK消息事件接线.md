## 三、怎么做（关键判据，逐条都有反例）

### 3.1 订阅 `"message"` 一个，⛔ 不订阅五个细分事件

证据是钉死版本 `wecom-aibot-python-sdk==1.0.2` 的源码
（`aibot/message_handler.py::_handle_message_callback`）：

```python
emitter.emit("message", frame)                # 每一条消息回调都先 emit 这个
...
if msgtype == MessageType.Text:  emitter.emit("message.text", frame)
elif ...
else: self._logger.debug(f"Received unhandled message type: {msgtype}")   # ⛔ 什么都不 emit
```

⇒ 按细分事件接线，**未知/新增 msgtype 的消息会静默消失**，与 TD-39 同形、同样无症状。

⚠️ `handle_frame` 会先把 `cmd == aibot_event_callback` 的帧岔给 `_handle_event_callback`
（emit 的是 `"event"`）⇒ `message` 只承接消息回调，⛔ 不承接 `enter_chat` 之类事件。

### 3.2 回调纪律：只往队列里放，⛔ 不碰库

sqlite 连接默认只能在创建它的线程里用，SDK 回调跑在它自己的事件循环线程上。回调里碰库
会在最不该出错的那一刻抛异常，异常再被 pyee 转成 `error` 事件——**TD-39 那条重连链正是
这么断的**。⇒ 回调只 `events.put((EVENT_INBOUND_MESSAGE, now(), frame))`，落库在值守线程。

时间在**回调那一刻**取，⛔ 不在值守线程那头取：队列可能正排着队，而这个时间戳同时是
归档目录的分日依据。

### 3.3 入站消息**也**要喂 `on_activity`

收到消息是"对端在应答"的铁证。不喂的话，一个只收消息、久未心跳的连接会被看门狗按
`last_event_at` 判成假死拆掉（TD-42 的判据）。

### 3.4 `thread_id` 取 `chatid`，⛔ 不自己按 chattype 分支

SDK `client.send_message` 的 docstring 逐字：「chatid: 会话 ID，单聊填用户的 userid，
群聊填对应群聊的 chatid」——与 design D3 对 `thread_id` 的定义**完全同义**。自己再分一次
支就是多一处会漂移的真源。`chatid` 缺席时退回 `from.userid`（只对单聊成立）并留 WARNING。

### 3.5 🔴 字段名表未经实测 ⇒ 对不上必须**炸得很响**

SDK 把 `frame["body"]` **原样透传**（`WsFrame = Dict[str, Any]`，`types.py` 只定义了
`cmd`/`headers`/`body`/`errcode`/`errmsg` 五个顶层键，body 内部一个字段都没定义）。
⇒ `msgid` / `msgtype` / `from.userid` / `chatid` / `text.content` 这张表来自**协议文档**，
不是实测。集中成 `channel.py` 的 `_BODY_*` 常量（8.6 核对真实报文时只改这一处），
对不上时抛 `InboundFrameShapeError` ＋ 记 ERROR，⛔ 不静默跳过。

🔴 **报错只列键名、⛔ 不列取值**——取值是同事的 `userid` 与聊天正文（个人信息），而报错
最常见的去处（日志、聊天、issue）恰恰最不设防。与 `MissingCredentialsError` 同一条纪律。

### 3.6 畸形报文 ⛔ 不许打死值守线程

值守线程是独占库连接的那一条。它被一条坏报文打死 ⇒ 存活戳停更 ⇒ 看门狗判假死 ⇒ 终止
进程 ⇒ launchd 拉起 ⇒ 同一条消息再来一次 ⇒ **无限重启循环**。⇒ 异常一律吞在
`apply_inbound_message` 里，⛔ 但必须记 ERROR（吞成 `pass` 等于把丢消息也变成静默）。

### 3.7 守卫测试是**删**，⛔ 不是加豁免

`test_this_chapter_wires_no_message_handling` 守的是第 7 章的范围，接线做完之后它守的
东西已经反过来。⛔ 不许改成"允许接 archive/queue"的豁免版留着——那条断言什么也不守，
只是噪音。换成正向断言：断"接上了"（含一条真的让 `liaison_message` 多一行的行为测试）。
