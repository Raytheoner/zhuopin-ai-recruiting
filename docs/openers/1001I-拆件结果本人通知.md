## 二、交付物

1. **起活失败通知**（dispatch 四类失败：章程读不到／日志建不了／进程创建异常／未预期异常）：
   失败时向 `owner_notify_outbox` 写一行——正文含：信件编号（若有）、`msgid`、失败原因、
   日志路径、时刻；`dedupe_key = "unpack-dispatch-failed:{msgid}"`（同键只一条）。
   写库失败只记日志、不上抛（与审计同基调）。`skipped_busy` **不通知**（避免噪音）。
2. **会话结束通知**：新增 `tools/liaison/unpack/session_runner.py` 作为**会话 wrapper**——
   它 spawn codex 子进程、原样转发 stdin（prompt）、等子进程结束后向 `owner_notify_outbox` 写一行：
   正文含 `msgid`、`exit_code`、日志路径、耗时；`dedupe_key = "unpack-session-exit:{msgid}"`。
   `dispatch.py` 改为起 wrapper（锁文件记 wrapper pid，仍满足「会话活着＝锁活着」）。
   ⛔ wrapper 只做"等待＋通知"，**不读会话输出内容、不判定结论**（结论仍按章程落 `docs/`）。
3. **测试**：新增/补充 `tools/liaison/tests/test_unpack_dispatch.py`／`test_owner_notify.py` 相邻用例：
   失败→outbox 一行且幂等；busy→不通知；wrapper 退出码正确落库；正文不含任何候选人个人信息。
4. 防回归：`tests/test_unpack_guard_hook.py` 保持全绿（hook 语义未动）。
