【二、要改什么（TDD：先让断言红，再改实现）】

**根因**（已定位到行，⛔ 不必重新调查）：`aibot==1.0.2` 的 `WSClientOptions.heartbeat_interval`
**单位是毫秒**（`types.py:49` 默认 `30000`，docstring 明写「心跳间隔（毫秒）」；`ws.py:299`
实际 `asyncio.sleep(interval/1000)`）。`session_client.py:37` 的 `DEFAULT_HEARTBEAT_SECONDS = 30`
被 `build_ws_options` 原样传入 ⇒ 解读为 **30 毫秒** ⇒ 频率 ×1000。

🔴 **先做这一步，⛔ 不要跳过**：现有断言
`tools/liaison/tests/test_session_client.py:175`

```
assert options.heartbeat_interval == session_client.DEFAULT_HEARTBEAT_SECONDS
```

是**同义反复**——拿传进去的值跟它自己比，单位错成什么样它都绿。**这正是这个 bug 活到
真实建连才暴露的原因。** 修实现之前，先把它换成**绝对值**断言（`== 30_000`），确认它在
当前代码下**真的红**，再动实现。⛔ 不许"改完实现顺便把断言也改了"——那样你不知道断言
到底有没有判据力。

**改法（Shao Peishen 答 `1a`）**：
1. 常量改名并按毫秒取值：`DEFAULT_HEARTBEAT_SECONDS = 30` → `DEFAULT_HEARTBEAT_MS = 30_000`，
   docstring 写明「单位是毫秒，SDK 契约见 `aibot/types.py:49`」。
   ⛔ **不许只把取值 30 改成 30000 而留着 `_SECONDS` 的名字**——那正是本条的成因。
2. 全仓搜旧名替换干净：`grep -rn "DEFAULT_HEARTBEAT_SECONDS" .`（含 `build_ws_options` 的
   关键字默认值与测试）。
3. 断言补两条，**都要能在根 venv 里跑**（根 venv 按 design D10 不装 SDK）：
   - 值断言：`build_ws_options(...)` 得到的 `heartbeat_interval == 30_000`
     （现有那条用 `pytest.importorskip("aibot")`，在根 venv 恒 skip，⛔ 不能只靠它）
   - **AST 级钉子**：照抄同文件里
     `test_ws_options_source_pins_the_reconnect_ceiling_to_unlimited` 的做法，不依赖 SDK
     也能挡住"有人把 30_000 改回 30"。⚠️ 断言里写明**为什么是 30000 而不是 30**，
     否则下一个人只会觉得这个数很怪。

【三、必须一并复核 `reconnect_interval`（同形状、未爆）】

处置：⛔ **不要顺手给它加传参**（那会改变重连行为，超出本条范围）。只把
`session_client.py:22-25` 那段注释改对，写明 SDK 的封顶是毫秒口径、本模块不传该参数、
两层的"同一个数"说法作废。
