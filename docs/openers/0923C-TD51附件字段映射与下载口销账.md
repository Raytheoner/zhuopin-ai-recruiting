## 二、动作

① **填三条字段路径**进 `tools/liaison/frames.py::ATTACHMENT_FIELD_PATHS_BY_MSGTYPE`（每条注释写「依据：`data/liaison/logs/liaison.log:274`，2026-09-21 11:08:40」）：
   - `download_url` ← `body.file.url`
   - `aes_key` ← `body.file.aeskey`
   - `filename` ← **该帧没有这个键**。落盘命名方案（按优先级）：
     a. 若 SDK `download_file` 的响应本身带文件名/`Content-Disposition`，优先取那个；
     b. 否则用 `{msgid}` 作为文件主干名，扩展名从下载字节的魔数判定（至少覆盖 `%PDF-`→pdf、
        `PK\x03\x04`→（docx/xlsx/pptx 皆此魔数，退化处理为 `.docx`，因为汤丽萍这次发的就是 doc 类）、
        `\xD0\xCF\x11\xE0`→doc（旧版二进制 Office）；
     c. 都判不出 ⇒ 用 `.bin`，并在归档记录里追加一个字段/备注注明「扩展名不确定，凭内容自行判断」。
   把这套命名逻辑写成一个独立小函数（如 `_guess_attachment_filename(msgid, content_bytes)`），
   带单测覆盖 a/b/c 三条路径。

② **把 `test_production_attachment_table_is_empty_and_fails_closed_on_a_file_frame` 改成正向断言**
   （现在应该是走真实下载路径成功落盘，而不是再断言"表空即拒绝"）。

③ **接 `InboundPorts.download` 真实 SDK 适配器**：
   - 值守线程发起下载时，用 `asyncio.run_coroutine_threadsafe(client.download_file(ref.download_url, ref.aes_key), loop).result(timeout)`
     把协程投给主线程的事件循环；
   - `loop` 复用 `LoopStopper` 抓到的把手；`client` 必须从 `make_sdk_connect` 每次重建里取**最新**的
     （⛔ 不能缓存第一次拿到的 client——`_started` 闩锁，细节见 `make_sdk_connect` 的 docstring）；
   - ⛔ 不在值守线程另起事件循环；⛔ 不把数据库连接带过这条线程边界。
