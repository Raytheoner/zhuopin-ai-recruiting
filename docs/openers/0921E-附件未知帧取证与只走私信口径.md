# [Mac]0921E 附件接收第一步：未知帧结构取证 ＋ 口径落地「附件只走私信」

## 零、为什么

2026-09-20 汤丽萍在群「人力AI保障组」16:30 发了 `10个岗位需求.doc`（41.5K），17:04 连发三条
`@MAC机器人` 文本（`人事部#2` 决策点 a／b／c）。实际进到归档与信号的**只有 a、b 两条文本**：
附件一条没进，决策点 c 那条也没进。`人事部#3` 因此只能判「待人」（`0921C`）。

附件收不进的机制根因在 `tools/liaison/frames.py::compute_attachment_ref`：
`ATTACHMENT_FIELD_PATHS_BY_MSGTYPE` 为空 ⇒ 抛 `AttachmentFieldsUnverifiedError` 并 fail-closed。
它不是 bug，是**刻意**的——没有真实帧就不许猜 `url`/`aeskey`/`filename` 落在哪个键上。
⇒ 要修就必须先**拿到一条真实帧的结构**。本条就是把「下次来帧时能取到证」这件事做好。

🔴 Shao Peishen 2026-09-21 定的口径：**附件只走机器人私信（单聊）**，群里发的附件不收。

## 二、动作

① **未知附件帧取证**：捕获 `AttachmentFieldsUnverifiedError` 时，把该帧的**键名结构**落到
   `data/liaison/logs/unknown-attachment-frames/<时间戳>-<msgtype>.json`，并让原告警指向该文件。
   🔴 **只记键路径与值的类型名**（如 `{"file.url": "str", "file.filesize": "int"}`），
   ⛔ **绝不写入任何值**——不写 url、不写 aeskey、不写 filename、不写字节，一个原值都不许落盘。
   ⛔ 不改变 fail-closed 行为本身：照样抛错、照样不收，只是多留一份可取证的结构。
② **口径落地**：附件接收只在**单聊（私信）**帧上尝试；群帧的附件一律忽略并记一行 info
   「附件只走私信，已忽略群帧附件」。⛔ 不动文本帧的既有处理路径。
③ **诊断决策点 c 漏收**：查 2026-09-20 17:04 之后的入站日志，判断第三条 `@MAC机器人` 文本
   为何未进归档（时间窗、去重、群帧过滤、服务存活任一）。**只诊断 ＋ 把结论写进 opener 收工报告**，
   ⛔ 不改任何判定逻辑——改法要等结论出来再单独派。
④ **测试**：新增 `tests/test_attachments_unknown_frame_dump.py`，断言：产出文件只含键名与类型名、
   不含任何值；群帧附件被忽略且不抛错；单聊未知附件帧仍 fail-closed 且留下结构文件。
   narrow 跑：`venv/bin/python -m pytest tests/test_attachments_unknown_frame_dump.py -q`，⛔ 不跑全量。
⑤ **队列**：把「决策点 c 漏收」与「附件只走私信」两条**并入既有 `Q-01` 行**的问题列
   （Shao Peishen 口径：新发现并入同族既有行）。⛔ 不另立新行、⛔ 不改 `Q-01` 的状态与答复列。
⑥ 提交 ①②④⑤ 并 `push`。
