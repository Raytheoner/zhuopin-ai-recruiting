## 二、交付物

1. **dispatch 传参**：`dispatch.py` 起 `session_runner` 时补两个参数
   `--checkpoint <prompt 用的检查点 ISO>`、`--letter-number <信件编号或空>`（来源＝本次 prompt 同一份取值）。
2. **runner 代提交＋清信号**（`session_runner.py`，在引擎 `wait()` 之后、写退出通知之前）：
   - 仅当 **exit_code == 0** 时才尝试；否则记日志、通知备注"会话非零退出，未代提交、未清信号"，结束。
   - 用 `git status --porcelain -- <CHARTER_WRITABLE_PATHS 四个路径>`（从 `dispatch` import，⛔ 不抄第二份）：
     - **无改动** ⇒ 视为已落档，直接进第 3 步；
     - **有改动** ⇒ `git add -- <列出路径>` → `git commit -m "chore(unpack): {信件编号} 回灌落档（{msgid 前 8}）"`；
       commit 失败 ⇒ 记 ERROR、通知备注原因、**不清信号**（fail-closed）。
   - 白名单之外的路径 ⛔ 一律不 add、不 commit（`git status` 里别人的改动原样留着）。
3. **清信号**：代提交成功后执行
   `{sys.executable} -m tools.liaison unpack-signal --clear --before {checkpoint}`（cwd=仓库根、`PYTHONPATH=.`），
   保留检查点之后的新信号；失败 ⇒ 记 ERROR、通知备注原因。
4. **退出通知补备注**：`build_session_exit_notice(..., note=…)` 里写清代提交/清信号结果
   （如「代提交 3 文件｜信号已清（before=<ts>）」或失败原因）。⛔ 正文不含归档件内容。
5. **测试**：`tools/liaison/tests/test_unpack_dispatch.py` 补：无改动→不 commit 但清信号；
   有改动→add+commit 后清信号；commit 失败→不清信号且通知带失败备注；非零退出→不动 git、不清信号；
   ⛔ 断言不出现白名单外路径被 add。
