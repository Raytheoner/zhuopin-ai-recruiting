# [Mac]0920F 接力文件归档瘦身

## 零、为什么

`docs/session接力.md` 现 57,835 B，体积闸 58 KB（`tests/test_doc_size_budget.py`），**余量不足 1.5 KB**。
再追加一条就会顶闸 ⇒ 看护者发车前的 pytest 不过 ⇒ 整批不发车。

## 一、做什么

1. 逐节判定哪些是**已闭环**：`###` 小节里的结论已落、且该节所有【状态】字段都不是「待派发／待发车／待答／在跑」⇒ 已闭环。
   拿不准 ⇒ **不标**，留在正文（宁可少归档一节，⛔ 不许误归档在途工作）。
2. 给已闭环小节的标题加「【已闭环】」（或把 `###` 标题整个划掉 `### ~~…~~`）。
3. 跑 `python3 scripts/archive_docs.py --apply`（原样搬进归档、带守恒校验）。
   ⛔ 不要手工剪贴、⛔ 不要为了过闸删内容、⛔ 不要调高上限。
4. 🔴 **保留区（这几节一律不标、不搬）**：
   - 「## 🔴 新 session 先看这一节」及其全部子节
   - 「## 二、下一步」里 2026-09-19 及以后的全部条目
   - 任何含「待派发」「待发车」「待答」「留步」字样的条目

## 二、完成判据（全过才算完）

1. `wc -c docs/session接力.md` ≤ **46080**（45 KB），且 ≥ **20480**（低于此说明搬过头，退回重做）
2. `archive_docs.py` 的守恒校验通过（脚本自己打印，⛔ 不许 `--force` 之类绕过）
3. `venv/bin/python -m pytest tests/test_doc_size_budget.py -q` 通过
4. `grep -c '待派发\|待发车\|待答\|留步' docs/session接力.md` 前后**相等**——在途工作一条都没被搬走

## 三、并发协议（逐字内嵌）

1. 只 `git add` 本条改到的路径（`docs/session接力.md` ＋ `archive_docs.py` 实际写到的归档文件 ＋ `docs/openers/0920F-*.md`）。⛔ 禁止 `git add -A` / `git add .` / `git commit -a` / `git stash`（含 `-u`）。
2. `git status` 里出现别人的改动是正常的，不要停下、不要问、不要顺手提交。
3. push 被拒 → `git pull --rebase --autostash origin main` 后重试，最多 3 次。⛔ 不要在 commit 前 pull。
4. 报 `.git/index.lock` 已存在 → 等 5 秒重试最多 5 次，⛔ 默认绝不删除该锁。

## 四、红线

⛔ 不删任何内容（只搬）；⛔ 不碰保留区；⛔ 不碰 `.51`；⛔ 不动工作区里任何未追踪文件。

## 五、收口

提交 + push，`git rev-list --count main..origin/main` 为 0；收工报告给出归档前后字节数、搬走的小节标题清单、判据 4 的前后计数。顶格打印 `OPENER_DONE`。
