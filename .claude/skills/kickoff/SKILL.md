生成一份**可一键复制**的开场 Prompt，用于新开 Claude Code 或 Cowork 会话。

目的是消灭"选错环境"这类错误——界面、Session 新旧、worktree 要不要，全部在 Prompt 里写死，人不需要判断。

## 先确认阶段

若用户没说清是哪个阶段，问一句。四个阶段对应四种环境配置：

| 阶段 | 界面 | Session | Worktree | 工作目录 |
|---|---|---|---|---|
| `openspec-propose` 需求与契约 | Cowork 或 CC 均可 | **新开** | ❌ 不要 | 主检出 |
| `spec-to-plan` 出实现计划 | **CC Desktop Code tab / 终端** | **新开** | ❌ 不要 | 主检出 |
| `run-build` 写代码 | **CC Desktop Code tab / 终端** | **新开** | ✅ **要** | worktree 内 |

> **分支名不要指定**（2026-08-09 实测结论）。Claude Code Desktop 勾选 worktree 后会自己生成分支名，格式 `claude/<任务名>-dev-<hash>`，例如 `claude/m1-chapter0-demo-dev-b9e90f`，**不接受我们指定的名字**。Opener 里写死分支名只会导致 AI 为了对齐而多建一个 worktree。正确写法是：「确认当前在 worktree 内、不在 main/master 上」，并让它报出实际分支名。
>
> worktree 落在 `<项目根>/.claude/worktrees/<名字>/`，Claude Code 会自动写进 `.git/info/exclude`，**不需要在 `.gitignore` 里额外加规则**。
| `openspec-archive-change` 收口 | Cowork 或 CC 均可 | 新开 | ❌ 不要 | 主检出 |

> 为什么一律新开 session，见 docs/kickoff-由来.md「一律新开 session 的原因」。

例外：同一阶段被中断后**恢复**，可以利旧（`run-build` 有进度台账，重跑同一计划不会重复已完成的 Task）。

## 输出格式（固定模板，不要改结构）

用一个围栏代码块输出，方便一键复制。**代码块内不要出现 markdown 加粗、表格这类渲染标记**，纯文本。

### 编号与抬头（2026-08-19 起固定；口径以 `CLAUDE.md`「给 Paul 任务指令时的强制格式」为准，不一致以 CLAUDE.md 为准）

每份 Opener **代码块内的头两行**固定为标题行 +【设置】行，**两行都写在代码块里面，不写在外面**——它要跟着一起被复制进新会话，那边要能看到自己是谁、跑在哪。

```
[Mac]MMDDX-<主题短名>
【设置】执行环境: <CC / Cowork> ｜ Session: <新开 / 利旧+理由> ｜ 分支: <main / worktree 分支> ｜ worktree: <❌ 不勾 / ☑ 勾选>（<理由>）｜ 工作区: <绝对路径> ｜ 派发: <母 session 编号>
```

- `MMDD` 取**中国时间**当天日期。⚠️ **动手编号前先真的跑一次** `TZ=Asia/Shanghai date +%m%d`，
  ⛔ 不要用环境给的日期、也不要凭上一条 opener 的编号往下推

  > 成因与实证见 docs/kickoff-由来.md「MMDD 必须实跑的原因」。
- `X` 从 `A` 起按同批出场顺序递增；同一天再出新批，字母**接着往下排**，不要重头从 A 开始
- **序号只用字母**，紧跟在 MMDD 后面不加分隔（`0827A`）。⛔ 不要用数字序号——`082710`
  反解不出是 `0820`+`10` 还是 `0820`+`1`+`0`；历史上的 `0820-10` 那批按「历史不追改」保持原样
- **`-` 是 id 与主题的唯一分隔符，id 内不含 `-`**。⛔ 不要用空格分隔

  > 成因见 docs/kickoff-由来.md「id 用 `-` 分隔而非空格的原因」。

- **`[Mac]` 标的是执行机**，Win 端对应 `[Win]`

  > 成因见 docs/kickoff-由来.md「[Mac] 前缀值得占用字符的原因」。
- **主题短名要短**——这一行就是侧边栏的 session 名，长了会被截断。能一眼看出干什么即可，
  不要写"继续上次的工作"；范围/章节写进正文的【任务】段，不占标题位
- **可选第七项 `｜ 模型: Opus`**（2026-09-16 `0916C`）：项目默认 Sonnet，只有推理密集的 opener（openspec design、需求收敛、疑难调试）才写，Paul 看到就在模型选择器切 Opus；其余⛔ 不写。依据见 CLAUDE.md「模型分级」
- **【设置】六项一个都不能少**，用 ｜ 分隔写成**一行**，不要拆成多行；worktree 后面的括号写理由（如"只出分析与方案，不写代码"），不要只写符号
- 🔴 **`派发` ＝ 出这份 opener 的母 session 编号**（2026-09-08 定，Shao Peishen 提）。

  > 成因与实证见 docs/kickoff-由来.md「派发字段不能留空的原因（0908J 实证）」。

  四种取值，⛔ 不留空、不写"未知"、不写"上一个 session"这类指代：

  | 情形 | 写法 |
  |---|---|
  | 母 session 有编号 | 照抄编号，如 `[Mac]0908B` |
  | Cowork 会话派的 | 会话名，如 `Cowork·HR业务线-接力0903B` |
  | 他本人直接口述、无母 session | `Shao Peishen 口述` |
  | `run-lanes.sh` 无头起的块 | `run-lanes.sh` |

  ⚠️ 母 session **就是正在写这份 opener 的自己**——⛔ 不要填成"要执行它的那个 session"，那是子不是母。机器判据见 `scripts/hooks/check-opener-header.py` 判据③（只判字段在不在，不校验取值）
- **没有"小任务可以省略"这种例外**——省略就是让人猜，猜错的代价远大于多写两行

##### 🔴 "这不算 Opener" 是最常见的漏法（2026-08-26 实证）

本技能叫 kickoff、模板叫 Opener，会诱导出一个错误的自我豁免：**"我这只是会话中途让他去 CC 跑一条命令，不是开场 prompt，不用带头两行"**。

**没有这个豁免。** 口径以 `CLAUDE.md` 为准：**任何**要 Paul 去别处执行的指令都适用，不分场合——

- 会话中途临时让他去 CC 跑一条命令 → 要
- 只有一行 `git push` → 要
- 让他去执行某个握手文件（如"执行 `.claude/handoff/_next.md`"）→ 要
- 同一件事的第二次、第三次追加指令 → 要，编号沿用并加 `（修订N）`

> 实证与归因更正见 docs/kickoff-由来.md「标题行漏写的实证与归因更正（2026-08-26／08-27）」。

*自检*：**这段文字会被他复制到另一个界面去吗？** 会，就必须有头两行。

### 多份同出时必须给顺序/并行矩阵

一次给出 **≥2 份** Opener 时，代码块之外必须先给一张矩阵（只有一份时不写这段）。**不得只把 opener 并列列出、让他自己推断先后。**

逐项写明：

| # | 任务名 | 触碰区（会改哪些文件/目录） | 能否立即开工 · 可与谁并行 / 必须在谁之后 |
|---|---|---|---|

- 判据是**触碰区是否重叠**——重叠即串行，不重叠即可并行
- 必须串行的，写明谁先谁后、以及后一份依赖前一份的什么产出
- **不要设"闸门"式编排**（要求某段时间内别开其他 session）——那是伪装成机制的人工节奏控制。有依赖就彻底串行，能并发的全部并行

#### 每份可并行的 Opener 内必须逐字内嵌这四条

并发安全靠机器自愈，**不靠"他记得别同时开"**。下面四条逐字抄进 Opener 代码块的 `【并发协议】` 段（口径同 `CLAUDE.md`「多指令并行的硬规则」）：

1. 只 `git add` 本条明确列出的路径。禁止 `git add -A` / `git add .` / `git commit -a` / `git stash`（含 `-u`，会卷走别的泳道未提交的工作）——这是并行成立的唯一前提
2. `git status` 里出现别人的改动是正常的，不要停下、不要问、不要顺手提交
3. push 被拒 → `git pull --rebase --autostash origin main` 后重试，最多 3 次。⛔ 顺序不能反——不要在 commit 前 pull，并发下别人的未提交改动会让 rebase 直接失败（实测 `error: cannot pull with rebase: You have unstaged changes`），`--autostash` 会自动暂存再恢复，实测别人的改动完好
4. 报 `.git/index.lock` 已存在 → 等 5 秒重试最多 5 次，绝不删除该锁（另一个 session 正在用，删了会毁掉它的提交）

> 由来见 docs/kickoff-由来.md「并发四条内嵌的由来」。

#### 🔴 add 清单是**并行安全边界**，不是"只许动这些文件"的白名单（2026-09-09 定）

【提交】节列的路径，管的是 **`git add` 的范围**——它防的是把别的泳道的改动卷进本次提交。
⛔ **它不是任务范围**：执行方发现清单漏了一个**本任务必需**的文件时，
**照改，并在收工报告里单列一行说明改了什么、为什么清单里没有**。

⛔ **不许为了守清单交付一个不工作的东西。** 判据一问：
**不改这个文件，本条的产出还成立吗？** 答"不成立"就改。

> 实证见 docs/kickoff-由来.md「add 清单实证（0909AH／TD-39）」。

⚠️ 反过来同样成立：**⛔ 不许借这条顺手改无关文件**。可以多改的只有"不改就交付不了"的那些，
⛔ 不是"顺手一起清理了"的那些。

⇒ **写 opener 时的反向义务**：列【提交】清单前先问一句
**「这个改动要真正生效，接线在哪个文件？」**，把接线文件一并列进去。
漏接线文件是 opener 最常见的缺陷——正文写得再细，接线漏了产出就是死的。

### 🔴 一键复制铁律

**每份 Opener 必须是完整的、可直接整块复制的，绝不能让用户自己拼接或插入片段。**

- 有修正、补丁、附加约束 → **重新输出完整版**，把修正融进去，不要说"在 X 和 Y 之间插入这段"
- 一个代码块 = 一次粘贴 = 一个完整任务
- 若同一轮需要用户在两个不同环境各跑一次 → 给**两个各自完整**的代码块，并明确标号与先后顺序
- 代码块外用一两句说明"这块在哪跑、跑完看什么"，但**代码块本身必须自足**

> 由来见 docs/kickoff-由来.md「一键复制铁律的由来」。

### 字母池用尽（2026-09-08 补）

同一天 `A–Z` 用完（`Y`/`Z` 已被看护者占）时，**顺延用次日 `MMDD`** 编号，并在号池台账「主题」列注明「MMDD 编排，字母池用尽顺延」。⛔ 不用双字母、不重用已作废号。

### 🔴 判据不许写成「会随时间漂移」的形状（2026-09-10 实证）

**opener 里的前置判据，问的必须是「在不在」，⛔ 不是「在不在最近 N 条里」。**

⛔ 反例见 docs/kickoff-由来.md「判据禁止漂移——0910B 反例与同族旧教训」。

**判据自检一句话：这条判据的答案，会不会因为「别人在 main 上提交了几次」而改变？** 会 ⇒ 重写。

| ⛔ 漂移形状 | ✅ 稳定形状 |
|---|---|
| `git log --oneline -3 \| grep X` | `grep -n "X" <那个文件>`（问内容在不在） |
| 「应排在最近几条」 | `git log --oneline -S"X" -- <路径> \| tail -1`（**不带深度上限**） |
| 「pytest 应为 N passed」抄进 opener 当基线 | 开工时**现跑一次**取基线，只断言「不回归」 |
| **预占**尚未发车的号（`MMDD` 当场写死） | 发车当天实跑 `TZ=Asia/Shanghai date +%m%d` **现取**；⛔ 不预占（2026-09-11 实证：09-10 预占的 `0910L` 隔夜作废改 `0911A`） |
| 「diff 应为 5 文件 276 行」 | 发车前 `git diff <现网 HEAD>..main` **现算** |

同族旧教训（`0909P` 等）同见上条 docs/kickoff-由来.md 小节。

### 🔴 引用式 Opener（2026-09-03 Shao Peishen 定）

**正文超过 500 字（约 25 行）的 opener，⛔ 不再整段贴进聊天。** 正文写成文件，聊天只给 4 行引用块：

- 文件：`docs/openers/<MMDDX>-<主题短名>.md`，**一个 opener 一个文件**，文件头两行与引用块头两行**逐字相同**
  （标题行 + 【设置】行），后面才是 【一、…】 各节正文。用 Write 直接写进仓库（Cowork 侧写的文件他本机立刻可见，不用等提交）
- 引用块（这就是他要复制的全部）：

  ````
  ```
  [Mac]MMDDX-<主题短名>
  【设置】执行环境: CC ｜ Session: 新开 ｜ 分支: … ｜ worktree: … ｜ 工作区: 仓库根 ｜ 派发: <母 session 编号>
  开工第一件事：调 mcp__ccd_session_mgmt__set_session_title（session_id 传字面量 "self"），标题：[Mac]MMDDX-<主题短名>
  第二件事：读 docs/openers/MMDDX-<主题短名>.md 全文并逐节执行，本 session 的全部指令以该文件为准。文件不存在、或其首行编号与本块不一致 → 停下报我，⛔ 不要凭标题猜任务
  ```
  ````

- 🔴 **被引文件必须与派号同一次 commit 落档**（2026-09-10 定）：贴出引用块**之前**，
  `docs/openers/<MMDDX>-<主题短名>.md` 已写好、`docs/openers/号池台账.md` 已登记，两者落在**同一条 commit** 里。
  ⛔ 不许「先派号、正文随后补」，⛔ 不许只在聊天里派——接手 session 只会按「文件不存在即停」停下，一轮白跑。
  机器判据：`git show --stat <派号那条 commit>` 里**同时**出现该 opener 文件与 `docs/openers/号池台账.md`；
  两者缺任一 ⇒ 这个引用块还不能贴
- 正文文件的【提交】节必须把**自己的路径**列进 `git add`——opener 文件随任务一起进 git，这就是留痕与冷备份
- ≤ 500 字的（提交类、几步就完的）照旧直接贴，引用反而多一跳
- 编排文件 `OP-0820-全量编排.md` 里的**无头块不变**（`run-lanes.sh` 从那里抽正文）；看护者 opener 也走引用式，
  文件名 `docs/openers/MMDDZ-泳道批次看护.md`

### 🔴 同结果的方案只给一种（2026-09-04 Shao Peishen 定）

给他的每一处「怎么做」，若几种做法**结果相同**，只写人为参与最少、无歧义的那一种，⛔ 不写「A 或 B，你选」。
只有结果不同、且属他必须拍的（CLAUDE.md 不可代项、真正的取舍）才列选项，并且**必须附推荐**。
看护者报告的「下一步建议」同样适用。反例见 docs/kickoff-由来.md「同结果只给一种——0903Y 反例」。

### 🔴 凭据铁律

**任何 API key、密码、token 都不得出现在 Opener 里，也不得让用户贴进任何对话框。**

正确做法：Opener 让 AI 创建配置文件但把凭据行**留空**，然后明确告诉用户「用文本编辑器打开该文件自己填」。若 AI 在执行中反问凭据，标准答复是「不告诉你，我自己填」。

### 🔴 能自动化的一律自动化（2026-09-09 Shao Peishen 定）

原话：**「以后能改成全自动都全自动，减少人工干预少出错」。**

⇒ 写 Opener 时，**凡能写成脚本的人工步骤，一律写成脚本**。⛔ 不许因为「让他手动做一下更简单」
或「这一步只要 5 分钟」就把人放进环里——人工步骤有两重代价：**占他时间**，且**人是出错源**
（时机错、顺序错、忘了记时刻）。⚠️ 这条比「无人值守禁止提问」更宽：那条管的是定时场景，
**这条连交互式 Opener 也管**。

自检一问：**这一步真的只有人能做吗？** 答不出"只有人能做"的理由，就去写脚本。

> 实证见 docs/kickoff-由来.md「自动化三条的由来实证（0909AG／TD-39）」。

#### 自动化必须满足的三条，缺一条就退回人工

1. **自愈**：`trap ... EXIT INT TERM` 恢复现场，**外加一条独立兜底**
   （如关网前先 `( sleep 300; <恢复命令> ) & disown`）——脚本被 SIGKILL 时 `trap` 不执行，
   只有独立进程能救。⛔ 不许留下「脚本挂了就回不去」的状态
2. **无害预检**：先用一条**空操作**探权限（如已经是 on 时再 `setairportpower on`），
   不过就**当场退回人工模式并说明原因**，⛔ 不许硬闯、⛔ 不许假设有权限
3. **失联可续**：若自动化过程中 CC 自己会失去网络/工具能力，脚本必须**先把采样与恢复都写死**
   再起，CC 事后只读日志判读。⛔ 不许写成"跑到一半再看情况调整"

⛔ **三条之外仍属人工的**：需要凭据、需要对外发送、CLAUDE.md 列的不可代项——
这些**不因本条而自动化**，本条只管"技术上人能做、机器也能做"的那一类。

### 🔴 无人值守 prompt 禁止提问铁律

**任何将在定时 / 无人值守场景下运行的 prompt——cron、计划任务巡检、`/loop`、`ScheduleWakeup`——绝对禁止写入需要人当场回答的指令。**

非交互 session 没有人能回答，写了即空转或卡死，而且**不报错**：等有人想起来看结果时，才发现这一整段时间白跑了。唯一正确的写法是**预案覆盖**——把所有可能分支的处理方式提前列全（"若 X 异常则记录并继续下一项"，而不是"若 X 异常则问我要不要重启"），无法预案的歧义**只登记、不追问**。

自检：通读整份 prompt，凡出现「问我」「先确认一下」「要不要」「你希望」「如需…请告知」，一律改写成固定处理方式。

> 由来见 docs/kickoff-由来.md「无人值守禁止提问的由来」。口径同 `CLAUDE.md`「无人值守 prompt 禁止提问」。

## 各阶段的必备内容

### 通用（每份 Opener 都要有）

- **必须有 `【收工】` 段**，内容固定为两项，一项都不能少：
  1. **本次全部新增/修改/删除文件的清单**——逐个列出仓库相对路径，禁止"等若干文件""相关配置"这类概括
  2. **一条建议的 commit message**——首行 `<类型>: <一句话>`（类型取 `feat`/`fix`/`docs`/`chore`/`refactor`），需要展开时正文分条列

  > 由来见 docs/kickoff-由来.md「收工段两项要求的由来」。

- 前置检查里必须有一条：**确认能调用所需的 superpowers/openspec 能力，调不到就停**
- 凡 opener 要引用「企业AI转型」的资产，**必须给 GitHub raw 的文件级 URL**，⛔ 不得再写本地路径：

  ```
  https://raw.githubusercontent.com/Raytheoner/zhuopin-ai-transformation/master/<路径>
  ```

  > 迁出背景见 docs/kickoff-由来.md「企业AI转型资产引用——迁出改版背景」。
  >
  > 三条落地要点：**① 分支是 `master` 不是 `main`**，写错全 404；
  > **② 中文路径必须 percent-encode**（已实测可读）；
  > **③ 没有本地副本就没法 grep 模糊搜索**——opener 里⛔ 不许再写"去那边找找有没有现成的"，
  > 必须先自己 WebFetch 定位到具体文件，把 URL 写进 opener。
  >
  > 引入方式不变：「**读取参考 + 在本仓库自建实现**」，不 clone 进来、不跨仓库引用或拷贝文件。
  > 原来那条"可读不可写"的约束**已随迁出失效**——本地根本没有那个目录了，写冲突风险不复存在，
  > 现在要管的是**怎么读得到**。

#### 🔴 `## 机器判据` 节——完成判据必须有消费者（2026-09-20 `0920K`）

- 每份 opener **应当**有 `## 机器判据` 节，内含一个 ```bash 块；泳道自报 `OPENER_DONE` 不算数，
  `run-lanes.sh` 收工时自己在仓库根跑一遍，不过即 `GATE-FAIL`、停本泳道、标注不摘
- 以**退出码**为准：全过 `exit 0`，任一不符 `exit 1`。写法示例：
  `[ "$(grep -c X f)" -ge 1 ] || { echo "X 缺失"; exit 1; }`
- 🔴 判据块**只读、无副作用**：⛔ 不许 `git push/commit/reset/clean`、`rm -rf`、`sudo`、`curl/wget/ssh/scp`——
  命中即 `GATE-UNSAFE`，与失败同处置且**根本不执行**（连注释里出现也算命中，别写）
- 没有该节的 opener 不拦（向后兼容），但**新写的 opener 一律要有**；判据形状仍守上面「不许漂移」一节
- 由来：0920I 在一条 grep 判据实测为 0 时照样打了 DONE——判据只写在正文里、靠泳道自觉、没有消费者
