生成一份**可一键复制**的开场 Prompt，用于新开 Claude Code 或 Cowork 会话。

目的是消灭"选错环境"这类错误——界面、Session 新旧、worktree 要不要，全部在 Prompt 里写死，人不需要判断。

## 先确认阶段

若用户没说清是哪个阶段，问一句。四个阶段对应四种环境配置：

| 阶段 | 界面 | Session | Worktree | 工作目录 |
|---|---|---|---|---|
| `openspec-propose` 需求与契约 | Cowork 或 CC 均可 | **新开** | ❌ 不要 | 主检出 |
| `spec-to-plan` 出实现计划 | **CC Desktop Code tab / 终端** | **新开** | ❌ 不要 | 主检出 |
| `run-build` 写代码 | **CC Desktop Code tab / 终端** | **新开** | ✅ **要** | worktree 内 |

> **分支名不要指定**（2026-08-09 实测结论）。Claude Code Desktop 勾选 worktree 后会自己生成分支名，格式 `claude/<任务名>-dev-<hash>`，例如 `claude/m1-chapter0-demo-dev-b9e90f`，**不接受我们指定的名字**。Opener 里写死分支名只会导致 AI 为了对齐而多建一个 worktree。正确写法是：「确认当前在 worktree 内、不在 main/master 上」，并让它报出实际分支名。
>
> worktree 落在 `<项目根>/.claude/worktrees/<名字>/`，Claude Code 会自动写进 `.git/info/exclude`，**不需要在 `.gitignore` 里额外加规则**。
| `openspec-archive-change` 收口 | Cowork 或 CC 均可 | 新开 | ❌ 不要 | 主检出 |

**为什么一律新开 session**：上一阶段的会话里塞满了它自己的产物与推理，接着用会把新任务锚定在旧结论上。重跑一份计划时尤其明显——旧会话会不自觉地复述旧计划。OpenSpec 官方也建议实现前清空上下文。

例外：同一阶段被中断后**恢复**，可以利旧（`run-build` 有进度台账，重跑同一计划不会重复已完成的 Task）。

## 输出格式（固定模板，不要改结构）

用一个围栏代码块输出，方便一键复制。**代码块内不要出现 markdown 加粗、表格这类渲染标记**，纯文本。

### 编号与抬头（2026-08-19 起固定；口径以 `CLAUDE.md`「给 Paul 任务指令时的强制格式」为准，不一致以 CLAUDE.md 为准）

每份 Opener **代码块内的头两行**固定为标题行 +【设置】行，**两行都写在代码块里面，不写在外面**——它要跟着一起被复制进新会话，那边要能看到自己是谁、跑在哪。

```
[Mac]MMDDX-<主题短名>
【设置】执行环境: <CC / Cowork> ｜ Session: <新开 / 利旧+理由> ｜ 分支: <main / worktree 分支> ｜ worktree: <❌ 不勾 / ☑ 勾选>（<理由>）｜ 工作区: <绝对路径>
```

- `MMDD` 取**中国时间**当天日期。⚠️ **动手编号前先真的跑一次** `TZ=Asia/Shanghai date +%m%d`，
  ⛔ 不要用环境给的日期、也不要凭上一条 opener 的编号往下推

  > *为什么必须实跑*：开发机在美东（EDT），**比中国时间晚 12 小时**——本机的晚上就是中国的次日中午。
  > 照本机日期编号，跨过那条线之后出的 opener 会集体落在"昨天"，而**编号错了不报错**，
  > 只在日后跨会话对账时对不上。实证：2026-08-27（中国时间）出的一批全被编成了 `0826-*`，
  > 是 Shao Peishen 问「这个是否改成 0827 更合适」才发现的。
  > ⚠️ 这条不适合做成 hook 机器拦——重发历史 opener 时编号本就该保持不变（见下方「重发」一节），
  > 拦了会误伤。所以它只能靠**出 opener 前实跑一次命令**这个动作来保证。
- `X` 从 `A` 起按同批出场顺序递增；同一天再出新批，字母**接着往下排**，不要重头从 A 开始
- **序号只用字母**，紧跟在 MMDD 后面不加分隔（`0827A`）。⛔ 不要用数字序号——`082710`
  反解不出是 `0820`+`10` 还是 `0820`+`1`+`0`；历史上的 `0820-10` 那批按「历史不追改」保持原样
- **`-` 是 id 与主题的唯一分隔符，id 内不含 `-`**。⛔ 不要用空格分隔

  > *为什么弃用空格*：主题短名常以 ASCII 开头（`audit U1计划`、`.51整机重启`），
  > `[Mac] 0826-D audit U1计划` 肉眼一扫读不出 id 在哪儿结束。`-` 唯一且紧凑，无歧义。
  > 主题里再出现 `-` 不影响解析——判据是**第一个** `-`。

- **`[Mac]` 标的是执行机**，Win 端对应 `[Win]`

  > *为什么值得占这几个字符*：Win 笔记本与 Mac 两台都在跑。启用 Remote Control
  > （从 claude.ai / App 控制 Claude Code）后，那一侧列出的是**跨机器**的 session，
  > 没有这个前缀就分不清哪条在哪台上。⚠️ 它标的是机器不是界面——
  > ⛔ 不要写成 `[CC]`：Code tab 下条条都是 CC，零分辨力。
- **主题短名要短**——这一行就是侧边栏的 session 名，长了会被截断。能一眼看出干什么即可，
  不要写"继续上次的工作"；范围/章节写进正文的【任务】段，不占标题位
- **【设置】五项一个都不能少**，用 ｜ 分隔写成**一行**，不要拆成多行；worktree 后面的括号写理由（如"只出分析与方案，不写代码"），不要只写符号
- **没有"小任务可以省略"这种例外**——省略就是让人猜，猜错的代价远大于多写两行

##### 🔴 序号必须查号池台账再出（2026-08-27 一天撞 4 次）

台账在 `docs/openers/OP-0820-全量编排.md` 顶部「🔢 号池台账」。**两步，缺一必撞**：

1. **出号前查**——⚠️ `grep` 仓库只查得到**已登记的**，所以第 2 步才是关键
2. **给出后当场登记进台账**，哪怕那份 opener 不写进编排文件正文

*实证*：08-27 `0827E` 被派给三个不同 session（提交 session 命名根治／提交 opener 补丁／
提交命名实测与自检），`0827D` 撞两次。根因不是记性——是**提交类、清理类这些一次性
opener 只出现在聊天记录里，从不落档** ⇒ 下一轮 grep 只看得到编排文件里那几个
（`A/B/C/Z`）⇒ 每轮都判定 `D/E` 是空号 ⇒ 必然重派。

⚠️ **撞号会把 `set_session_title` 那条规则的价值清零**——侧边栏三条同名，照样分不清。
⚠️ **Cowork 接力号与 CC 共用同一号池**；`Z` 固定留给看护者，不派作他用。
⚠️ 台账只记已知的，**claude.ai 侧边栏才是真身**，拿不准就让 Shao Peishen 看一眼。

##### 🔴 "这不算 Opener" 是最常见的漏法（2026-08-26 实证）

本技能叫 kickoff、模板叫 Opener，会诱导出一个错误的自我豁免：**"我这只是会话中途让他去 CC 跑一条命令，不是开场 prompt，不用带头两行"**。

**没有这个豁免。** 口径以 `CLAUDE.md` 为准：**任何**要 Paul 去别处执行的指令都适用，不分场合——

- 会话中途临时让他去 CC 跑一条命令 → 要
- 只有一行 `git push` → 要
- 让他去执行某个握手文件（如"执行 `.claude/handoff/_next.md`"）→ 要
- 同一件事的第二次、第三次追加指令 → 要，编号沿用并加 `（修订N）`

*实证*：2026-08-26 发现左侧会话列表里近期会话**全部丢失编号**，而更早的 `【OP-0820-*】` 一批都有。原因是某条会话连续给出八份中途指令，全部用了 `界面／Session／分支／Worktree` 四行式、一份都没带标题行。

> ⚠️ **当时对这条实证的归因是错的**（2026-08-27 更正）：以为「侧边栏拿不到标题行就用首句猜」，
> 实际侧边栏根本不看首行，用的是 Haiku 摘要——详见下一节。
> **但这条实证本身仍然成立**，只是它证明的是另一件事：缺头两行时，**被复制进去的那个
> session 自己不知道跑在哪、该不该勾 worktree**，这才是头两行的真正用途。
> 编号的可 grep 性另由「会话命名」那节的两条路保证。

*自检*：**这段文字会被他复制到另一个界面去吗？** 会，就必须有头两行。

#### 🔴 重发时必须整块重发，头两行一起带上

改版、收窄范围、修错之后重新给出同一份 Opener，**必须把标题行 +【设置】行一起重发**，不得只丢一个光秃秃的代码块。内容变了但仍是同一件任务时，编号保持不变，在任务名后加 `（修订N）`。

**自检一问：把这个代码块单独发给一个没读过背景的人，他能一眼说出这是哪件任务、跑在哪吗？** 答不上就是缺头两行。

*为什么*：聊天里 opener 总是被孤立复制的——收到一个无头代码块，人得往回翻十几屏找"这块是哪个任务"，找错就跑错环境。实证来自企业AI转型的真实反馈：「虽然我可以推断，第一张图是哪个任务的 Opener 不明晰」。

### 多份同出时必须给顺序/并行矩阵

一次给出 **≥2 份** Opener 时，代码块之外必须先给一张矩阵（只有一份时不写这段）。**不得只把 opener 并列列出、让他自己推断先后。**

逐项写明：

| # | 任务名 | 触碰区（会改哪些文件/目录） | 能否立即开工 · 可与谁并行 / 必须在谁之后 |
|---|---|---|---|

- 判据是**触碰区是否重叠**——重叠即串行，不重叠即可并行
- 必须串行的，写明谁先谁后、以及后一份依赖前一份的什么产出
- **不要设"闸门"式编排**（要求某段时间内别开其他 session）——那是伪装成机制的人工节奏控制。有依赖就彻底串行，能并发的全部并行

#### 每份可并行的 Opener 内必须逐字内嵌这四条

并发安全靠机器自愈，**不靠"他记得别同时开"**。下面四条逐字抄进 Opener 代码块的 `【并发协议】` 段（口径同 `CLAUDE.md`「多指令并行的硬规则」）：

1. 只 `git add` 本条明确列出的路径。禁止 `git add -A` / `git add .` / `git commit -a`——这是并行成立的唯一前提
2. `git status` 里出现别人的改动是正常的，不要停下、不要问、不要顺手提交
3. push 被拒 → `git pull --rebase --autostash origin main` 后重试，最多 3 次。⛔ 顺序不能反——不要在 commit 前 pull，并发下别人的未提交改动会让 rebase 直接失败（实测 `error: cannot pull with rebase: You have unstaged changes`），`--autostash` 会自动暂存再恢复，实测别人的改动完好
4. 报 `.git/index.lock` 已存在 → 等 5 秒重试最多 5 次，绝不删除该锁（另一个 session 正在用，删了会毁掉它的提交）

*为什么*：并行跑两条线改同一个文件，冲突不会在写的时候报错，会在提交时才发现，而那时两边的改动都已经写完了。事前列触碰区 + 内嵌自愈四条，是唯一便宜的防法。

### 🔴 一键复制铁律

**每份 Opener 必须是完整的、可直接整块复制的，绝不能让用户自己拼接或插入片段。**

- 有修正、补丁、附加约束 → **重新输出完整版**，把修正融进去，不要说"在 X 和 Y 之间插入这段"
- 一个代码块 = 一次粘贴 = 一个完整任务
- 若同一轮需要用户在两个不同环境各跑一次 → 给**两个各自完整**的代码块，并明确标号与先后顺序
- 代码块外用一两句说明"这块在哪跑、跑完看什么"，但**代码块本身必须自足**

*为什么*：手工拼接是纯粹的出错来源，且错了往往不报错——比如漏掉 Global Constraints 修正，后面每轮 review 都是瞎的，但过程看起来一切正常。

### 🔴 凭据铁律

**任何 API key、密码、token 都不得出现在 Opener 里，也不得让用户贴进任何对话框。**

正确做法：Opener 让 AI 创建配置文件但把凭据行**留空**，然后明确告诉用户「用文本编辑器打开该文件自己填」。若 AI 在执行中反问凭据，标准答复是「不告诉你，我自己填」。

### 🔴 无人值守 prompt 禁止提问铁律

**任何将在定时 / 无人值守场景下运行的 prompt——cron、计划任务巡检、`/loop`、`ScheduleWakeup`——绝对禁止写入需要人当场回答的指令。**

非交互 session 没有人能回答，写了即空转或卡死，而且**不报错**：等有人想起来看结果时，才发现这一整段时间白跑了。唯一正确的写法是**预案覆盖**——把所有可能分支的处理方式提前列全（"若 X 异常则记录并继续下一项"，而不是"若 X 异常则问我要不要重启"），无法预案的歧义**只登记、不追问**。

自检：通读整份 prompt，凡出现「问我」「先确认一下」「要不要」「你希望」「如需…请告知」，一律改写成固定处理方式。

*为什么*：本项目已经在用 `/loop`、`ScheduleWakeup` 这类无人值守重新触发的机制，将来还会有"每天检查 `.51` 服务是否存活"这类定时巡检。企业AI转型的巡逻 prompt 至今恰好没有提问句，但那**纯属惯例、规则从未写下**——一旦有人复制交互式模板去建定时任务，提问句就会被带进去。口径同 `CLAUDE.md`「无人值守 prompt 禁止提问」。

## 固定模板


## 各阶段的必备内容

### 通用（每份 Opener 都要有）

- **必须有 `【收工】` 段**，内容固定为两项，一项都不能少：
  1. **本次全部新增/修改/删除文件的清单**——逐个列出仓库相对路径，禁止"等若干文件""相关配置"这类概括
  2. **一条建议的 commit message**——首行 `<类型>: <一句话>`（类型取 `feat`/`fix`/`docs`/`chore`/`refactor`），需要展开时正文分条列

  > *为什么*：这件事我们每次都在收工时手工重做一遍。更实际的问题是**未提交悬置**——
  > Cowork 根本不能提交（bash 在隔离 VM 里，对 `.git/` 只能写不能删），
  > 改动只能靠人复制清单到 Claude Code tab；清单不全，漏掉的文件就永远停在工作区。
  > 任务再小也不例外——只改一个字也要列出那一个文件，"小改动不用列"正是漏提交的来源。

- 前置检查里必须有一条：**确认能调用所需的 superpowers/openspec 能力，调不到就停**
- 凡 opener 要引用「企业AI转型」的资产，**必须给 GitHub raw 的文件级 URL**，⛔ 不得再写本地路径：

  ```
  https://raw.githubusercontent.com/Raytheoner/zhuopin-ai-transformation/master/<路径>
  ```

  > **2026-08-26 迁出改版。** 该项目已迁出 OneDrive，本地路径
  > `~/Library/CloudStorage/OneDrive-Personal/Projects/企业AI转型/` **同步后即消失**，
  > 写进 opener 会让 CC 当场扑空。
  >
  > 三条落地要点：**① 分支是 `master` 不是 `main`**，写错全 404；
  > **② 中文路径必须 percent-encode**（已实测可读）；
  > **③ 没有本地副本就没法 grep 模糊搜索**——opener 里⛔ 不许再写"去那边找找有没有现成的"，
  > 必须先自己 WebFetch 定位到具体文件，把 URL 写进 opener。
  >
  > 引入方式不变：「**读取参考 + 在本仓库自建实现**」，不 clone 进来、不跨仓库引用或拷贝文件。
  > 原来那条"可读不可写"的约束**已随迁出失效**——本地根本没有那个目录了，写冲突风险不复存在，
  > 现在要管的是**怎么读得到**。

### `spec-to-plan` 专属

- 前置检查：能否调用 `superpowers:writing-plans`
- 任务里必须点名**输入是哪几份 `spec.md` 的绝对路径**，并显式禁止用 `tasks.md` 当输入
- 完成标准必须含：Global Constraints 段逐字来自 `CLAUDE.md`（含「工程铁律」与「部署约束」）
- 不要做：不要开始实现、不要建 worktree

### `run-build` 专属

- Worktree 段要写清建完之后**手工补三样**：`.env`、本地 SQLite/`data/`、Python venv（都被 gitignore 挡着，git 不带过去，缺失时报错完全不像"文件没拷"）
- 前置检查：计划里有没有 Global Constraints 段（没有就停，回去重跑 `spec-to-plan`）
- 前置检查：`.superpowers/sdd/progress.md` 是否已存在（存在说明跑过一部分，已完成的 Task 不要重跑）
- 完成标准必须含：回勾 `openspec/changes/<change>/tasks.md` 的对应条目，**且只有 final review 通过才勾**
- 不要做：不要中途问"要继续吗"；不要 `git clean -fdx`（会毁掉进度台账）

## 注意

- 路径一律写**绝对路径**，不写"当前目录"
- 若某个前置条件你已经知道结果（比如刚验证过 LLM 域名连通），直接在 Opener 里写明结论，减少对方重复劳动
- Opener 之外，用一两句话说明**为什么是这个环境配置**，帮用户建立判断力，但这部分放在代码块外
