## 1. 令牌格式与校验内核（纯函数）

- [ ] 1.1 定下令牌文件格式与字段（签发者标识、签发时间、有效期、覆盖编号、逐条内容摘要、执行参数），写成可被机器解析的结构；⛔ 不引入任何密钥字段
- [ ] 1.2 实现 `compute_opener_digest`——给定编排文件内容与一个泳道编号，算出该条 opener 正文的摘要；纯函数、无 IO
- [ ] 1.3 实现 `validate_token`——纯函数，输入令牌结构 + 当前时刻 + 编排文件内容，输出「通过 / 拒绝 + 具体原因」；覆盖有效期、签发时间在未来、摘要逐条比对、参数白名单
- [ ] 1.4 参数白名单校验：只放行六项，`--chain` / `--model` / `--dry-run` 恒拒；编号字符集 `[A-Za-z0-9_.,-]`、数值为非负整数或小数；任一不合格整条拒绝，⛔ 不做跳过降级
- [ ] 1.5 单测：spec 中「令牌有有效期」「摘要不匹配整批拒绝」「参数白名单」三条要求的每个 Scenario 各一条用例，含「摘要只错一条也整批拒绝、对得上的那条不跑」的正面断言
- [ ] 1.6 单测：签发时间晚于当前时刻被拒；⛔ 不允许用「取绝对值」之类的宽容处理绕过

## 3. 扫描器主流程与拒绝留痕

- [ ] 3.1 实现扫描器骨架：唤醒 → 读已提交编排与令牌 → 校验 → 并发判定 → 发车或拒绝 → 退出；无任何交互分支
- [ ] 3.2 实现「标注 ∧ 令牌」合取判定：仅标注、仅令牌两种情形各自拒绝并记录对应原因
- [ ] 3.3 实现一次一销：原子重命名消费令牌，失败即视为被其它实例认领并直接退出，⛔ 不重试、不等待
- [ ] 3.4 实现并发判定：执行器进程已在跑则推迟本轮且**令牌保持未消费**；`.git/index.lock` 存在则推迟，⛔ 绝不删锁
- [ ] 3.5 实现日志：每一次拒绝/跳过/推迟都有时间戳 + 令牌标识 + 具体原因；空扫不刷屏但可据以确认扫描器在运行
- [ ] 3.6 调用执行器时只传令牌里经白名单校验过的参数，泳道过滤参数取值恒等于令牌覆盖的编号集合
- [ ] 3.7 单测：spec「拒绝必须留痕」两个 Scenario；断言不存在静默丢弃分支（穷举所有 return/exit 路径都有日志）
- [ ] 3.8 单测：两个扫描器实例并发时只有一个发车（真实进程或可控的原子操作桩，⛔ 不靠 sleep 碰运气）
- [ ] 3.9 单测：执行器已在跑时推迟且令牌未被消费——下一轮仍能用
