## Purpose

把业务经理口语化的用人需求，通过多轮追问转化为结构化、可被下游系统直接消费的岗位画像，并从中提取可自动判定的硬门槛规则。这是整条招聘链路的输入端，画像质量决定后面所有环节的方向。

## ADDED Requirements

### Requirement: 对话式需求发起

系统 SHALL 允许业务经理以自然语言发起用人需求，无需填写表单。发起动作 MUST 与具体通道解耦：同一套采集与追问逻辑 SHALL 同时支持 Web 页面与企业微信，新增通道不得要求修改采集逻辑。

#### Scenario: 一句话发起需求（Web 通道）

- **WHEN** 业务经理在 Web 页面输入"要个做嵌入式开发的，能写驱动"并提交
- **THEN** 系统创建一条岗位记录，状态为 `drafting`
- **AND** 在 30 秒内返回第一轮追问

#### Scenario: 一句话发起需求（企业微信通道）

- **WHEN** 业务经理在企微向招聘助手发送同样内容
- **THEN** 系统行为与 Web 通道一致：创建岗位记录、返回第一轮追问
- **AND** 产出的画像内容不因通道不同而不同

#### Scenario: 需求描述为空或与招聘无关

- **WHEN** 发送的内容无法识别为用人需求
- **THEN** 系统回复引导语说明可以怎么提需求
- **AND** 不创建岗位记录

### Requirement: 多轮追问补全

系统 SHALL 基于 ECU 领域知识库识别需求中的模糊项，并通过多轮追问补全，直至画像必填字段齐备或达到追问上限。

#### Scenario: 识别模糊项并追问

- **WHEN** 需求中出现"嵌入式开发"这类宽泛表述
- **THEN** 系统追问 MCU 平台族、是否涉及 AUTOSAR、是否有功能安全等级要求
- **AND** 每轮追问不超过 3 个问题

#### Scenario: 追问达到上限

- **WHEN** 追问轮次达到 5 轮仍有必填字段缺失
- **THEN** 系统停止追问，用"未指定"填充缺失字段并标记
- **AND** 在推送给业务经理确认时显式列出未指定项

#### Scenario: 业务经理中途放弃

- **WHEN** 业务经理在追问过程中超过 3 个工作日未回复
- **THEN** 系统发送一次提醒
- **AND** 再超过 3 个工作日未回复则将岗位置为 `abandoned`，保留已采集内容

### Requirement: 结构化岗位画像产出

系统 SHALL 产出结构化的岗位画像，包含通用招聘字段与 ECU 行业特化字段，且每个字段区分"必会"与"加分"。

#### Scenario: 产出完整画像

- **WHEN** 追问完成
- **THEN** 系统产出画像，至少包含：岗位名称、部门、编制数、学历要求、年限要求、核心技术栈（必会/加分分列）、项目经验要求、软技能关键词
- **AND** 包含 ECU 特化字段：`autosar_experience`、`functional_safety`、`mcu_family`、`diag_stack`、`sop_projects`、`toolchain`
- **AND** 画像符合预定义的 JSON Schema，字段类型与枚举值校验通过

#### Scenario: 模型返回不符合 Schema

- **WHEN** LLM 返回的结构不满足画像 Schema
- **THEN** 系统最多重试 2 次
- **AND** 仍失败则将该岗位置为 `needs_manual`，通知 HR 人工介入，不产出半成品画像

### Requirement: 硬门槛规则草案提取

系统 SHALL 从画像中提取可自动判定的硬门槛规则草案，供后续简历筛选环节使用。每条规则 MUST 可解释、可单独启停。

#### Scenario: 提取硬门槛

- **WHEN** 画像产出完成
- **THEN** 系统生成硬门槛规则草案，每条包含字段名、比较运算符、比较值、是否阻断
- **AND** 每条规则附一句人类可读的说明（用于将来向候选人解释淘汰原因）

#### Scenario: 主观要求不得进入硬门槛

- **WHEN** 画像中包含"沟通能力强""有责任心"这类主观描述
- **THEN** 系统 MUST NOT 将其转为硬门槛规则
- **AND** 这类描述只作为软技能关键词保留在画像中

### Requirement: 采集过程审计留痕

系统 SHALL 记录画像生成的完整可追溯信息。

#### Scenario: 记录生成快照

- **WHEN** 系统产出画像草案
- **THEN** 落库记录模型标识、模型版本、prompt 版本、temperature、输入哈希、原始响应、token 用量、生成时间
- **AND** 模型调用使用 `temperature=0` 且模型版本显式锁定，不使用 `latest` 类别名
