## 2. 地基：LLM 网关

- [ ] 2.1 **模型对比实测**（阻塞后续所有 LLM 相关任务）：至少三家供应商在中文简历/岗位描述上的 `json_schema` 遵循度、结构化抽取准确率、延迟、单价 — 产出对比结论文档
- [ ] 2.2 网关薄封装：统一调用入口，强制 `temperature=0`，模型版本显式锁定（禁止 `latest` 类别名）
- [ ] 2.3 双供应商切换与降级：主供应商失败自动切备用，切换事件记入 `analysis_run`
- [ ] 2.4 结构化输出：`json_schema` 优先、`json_object` + Pydantic 本地校验降级，两条路径都实现
- [ ] 2.5 校验失败重试至多 2 次，仍失败转 `needs_manual`，**不产出半成品**
- [ ] 2.6 每次调用自动写 `analysis_run`，无需业务代码显式调用

## 5. 需求解析 Agent（capability: job-profile-intake）

- [ ] 5.1 定义岗位画像 Pydantic Schema：通用字段 + ECU 特化字段（autosar_experience / functional_safety / mcu_family / diag_stack / sop_projects / toolchain）
- [ ] 5.2 ECU 领域知识库：术语表与追问触发规则（"嵌入式开发"→ 追问 MCU 平台族/AUTOSAR/功能安全）
- [ ] 5.3 需求识别：区分"是用人需求"与"无关消息"，后者回引导语且不建岗位记录
- [ ] 5.4 多轮追问 Agent（纯函数）：每轮至多 3 个问题，上限 5 轮
- [ ] 5.5 追问超限降级：用"未指定"填充并在确认卡片显式列出缺口
- [ ] 5.6 业务经理超时：3 个工作日提醒一次，再 3 天置 `abandoned` 并保留已采集内容
- [ ] 5.7 画像产出与 Schema 校验接线
- [ ] 5.8 硬门槛规则提取：字段/运算符/值/是否阻断 + 一句人类可读说明
- [ ] 5.9 **主观描述拦截**：断言"沟通能力强"这类表述不得进入 `hard_requirement`，只留在软技能关键词
