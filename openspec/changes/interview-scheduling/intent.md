# S-排期 面试排期 · intent（需求收敛结论 · 首轮备料）

> 来源：本文件「设计树与前沿」第 1 轮（备料），**尚未答题**。Shao Peishen 在本线答 `Q1a，…` 后由 Cowork 转写进「决策」并清「待答题」。本文件是 `openspec propose` 的输入。依据文档：`02-系统架构与MVP范围.md` §1 L0/L5、§2.1、§3「明确不在 MVP 内」；`01-开源调研与技术选型.md` §2.7；`CLAUDE.md` 数据模型要点／合规红线／部署约束；`docs/tech-debt.md` TD-8／TD-11；`docs/跟进信/README-跟进信清单.md` 收件面口径；`docs/roadmap/M2-intent.md` 立包后裁决 Q5；`docs/roadmap/任务驱动上线路线图.md` 波次 5。
> ⛔ 本稿不是 spec，不是现状描述。

## 目标
HR 在工作台批量确认「进入面试」后 → 系统登记面试官可用时段与候选人时段、检查冲突、生成邀约文案（带 AI 标识、经门禁）→ HR 发出并回填结果 → 面试完成／改期／取消写入 `application_stage_history`。使用者：HR（排、改、发）、面试官（登记时段、看当日安排）。

## M2 已自查的事实
- 范围定性：面试排期「明确不在 MVP 内」，「排期/Offer/入职是集成活不是 AI 活，等主链路验证完再接」；路线图放波次 5，「集成类活依赖人事部现用系统信息」（来源：`02` §3；`docs/roadmap/任务驱动上线路线图.md` 波次 5）。
- 外部系统：L0 列「企业微信（通知＋审批）· 日历 ·（二期）招聘渠道对接」；企微审批按钮须自建应用 `template_card` ＋公网 HTTPS 回调，群机器人无按钮无回调（来源：`02` §1；`01` §2.7）。
- 通道现状：aibot 是被动应答形态、**不能主动私信**；主动推送单聊需企微自建应用（agentid＋secret）；`.51` 无公网、无反向代理（来源：`docs/跟进信/README-跟进信清单.md` 收件面口径；`04-部署与门户挂载.md` §1）。
- 邀约外发门禁：`interview_invitation` 已登记为高风险类型，未经人工确认不外发；生产里尚无调用方（来源：`openspec/specs/outbound-approval-gate/spec.md`；TD-8）。
- 候选人联系方式口径：M2 立包后裁决 Q5「手机号只用于去重、哈希存储、明文不落库」；企微通讯录接口 2022-06-20 后不返回手机/邮箱、候选人手机号必须自建库（来源：`docs/roadmap/M2-intent.md` 立包后裁决；`01` §2.7）。⇒ 排期要联系候选人与本口径冲突 → Q2。
- 定时基础设施：本系统至今没有任何定时／调度基础设施，挂起提醒（TD-11）一次都未实现；提醒类动作须是带幂等键的 `effect_*` 节点、⛔ 不用 sleep 线程充数（来源：`docs/tech-debt.md` TD-11）。
- 数据模型：`stage.stage_type=interview`、`application_stage_history` 是所有报表基础、状态属投递不属候选人（来源：`02` §2.1；`CLAUDE.md` 数据模型要点）。
- 面试官侧载体先例：企微卡片已移阶段二，M2 D8 沿用 Web 工作台（来源：`docs/roadmap/M2-需求树草稿.md` Q8）。
- HR 现状：Excel ＋ 微信/邮件，年招几十到百人（来源：`01` §2.6；`02` §0）。
- 鉴权：`.51` 无正式鉴权、共享口令；M2 起处理真实简历前须可识别到人的登录＋访问留痕（来源：`04` §1；`CLAUDE.md` 部署约束 5）——排期涉真实候选人，同受此门槛。

## 决策（已从事实源自答，依据逐条列出；G1 时可逐条改）
- **D1 定位**：集成活、非 AI 活；排在主链路（M2 试运行）验证后，波次 5。依据：`02` §3；路线图波次 5。
- **D2 邀约必经门禁**：邀约文案由系统生成时带 AI 生成标识，外发一律走 `deliver_candidate_message()`；开关默认关。依据：`outbound-approval-gate` spec；TD-8；`CLAUDE.md` 合规红线。
- **D3 状态落流转事实表**：安排／改期／取消／完成都写 `application_stage_history`（`actor_type` 区分 human/agent），`stage_type=interview`。依据：`02` §2.1；`CLAUDE.md` 数据模型要点。
- **D4 面试官侧载体**：Web 工作台（时段登记＋当日安排页）；⛔ 不做企微卡片、不依赖 aibot 主动推送。依据：M2 D8；aibot 被动形态。
- **D5 提醒类动作与 TD-11 同批**：若纳入提醒，必须随定时基础设施一起建，一个带幂等键的 `effect_*` 节点，⛔ 不单独做半吊子。依据：TD-11。
- **D6 门槛**：排真实候选人前须登录＋访问留痕就位（同 M2 门槛）。依据：`CLAUDE.md` 部署约束 5。

- **D7 范围档（Q1b，Shao Peishen 2026-09-17 23:0x 答）**：半自动：(a) ＋ 系统生成邀约文案（带 AI 标识、经门禁）供 HR 复制发送，发出结果回填
- **D8 候选人联系方式存储口径（Q2b，Shao Peishen 2026-09-17 23:0x 答）**：进入面试阶段后允许明文联系方式（手机号／邮箱）加密入库：字段级加密、访问留痕、随留存策略到期删除；PIA 与合规验收 #1 文档相应扩展
- **D9 面试官日历来源（Q3a，Shao Peishen 2026-09-17 23:0x 答）**：不接日历：面试官在工作台登记可用时段（周视图）
- **D10 进入排期的入口（Q4a，Shao Peishen 2026-09-17 23:0x 答）**：只从 M2 批量确认「进入面试」进入——候选人必先上传简历、有 `application`；代价：非 M2 来源的候选人也要先走上传（但人才库因此完整）。
- **D11 启动时点（Q5a，Shao Peishen 2026-09-17 23:0x 答）**：按路线图波次 5（M2 试运行验证后）

```
S-排期
├─ A 范围档：内部登记 / 半自动生成邀约 / 候选人自助选时段                    ← Q1
│   └─ A1 候选人自助改期入口（一次性链接，对外通道）                        → 取决于 Q1，第 2 轮
├─ B 候选人联系方式存储口径（与 M2 Q5 哈希口径冲突）                          ← Q2
├─ C 面试官日历来源：工作台登记 / 企微日历 API（自建应用）                     ← Q3
├─ D 进入排期的入口：仅 M2 批量确认 / 允许手工新增候选人                      ← Q4
├─ E 启动时点：波次 5 / 提前与 M2 全量并行                                   ← Q5
├─ F 提醒（面试前 1 天等）：依赖 TD-11 定时基础设施                            ✅ D5（同批建，不重问）
├─ G AI 面试场次（M3 live）是否进排期                                       → 取决于 S-M3 Q1，第 2 轮
└─ H 现用排期流程／面试官清单／邀约话术（专员）                               → 待专员
```

## 建议交付单元（propose 时细化）
U1 面试域排期模型（`interview_slot`／面试官可用时段／冲突约束，挂 `application`）→ U2 工作台页（HR 排期、面试官时段登记、当日安排）→ U3 邀约文案生成＋门禁接线（`interview_invitation`）→ U4 流转事实与报表字段 →（可选）U5 提醒节点（随 TD-11 定时基础设施）。

## 不做
候选人自助选时段／改期（一期，视 Q1）；企微卡片；自动外发（开关默认关，开启属不可代）；AI 决定面试官人选；排 AI 语音面试场次（待 S-M3 Q1 定）。

## 不可代项（进 tasks 时标注）
候选人对外通道开启；候选人明文联系方式入库的合规口径（若 Q2b，须改 PIA／合规验收 #1 文档）；企微自建应用注册（账号权限）；`.51` 发版。
