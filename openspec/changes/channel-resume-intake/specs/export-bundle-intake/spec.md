## Purpose

HR 从平台导出的 ZIP 包直接传，系统替 HR 把包拆开、逐文件走既有的上传闸与解析路径，坏文件单个拒收不拖累整包。

## ADDED Requirements

### Requirement: 接受 ZIP 导出包

系统 SHALL 在既有批量上传入口额外接受 `.zip` 文件，展开其中的 PDF 与 Word 文件（允许一层子目录），每个展开出的文件 MUST 走与单文件上传完全相同的接收路径（岗位、样本类别、内容哈希去重、访问留痕）。非白名单文件与损坏文件 MUST 逐个拒收并给出原因，MUST NOT 影响同包其他文件。ZIP 展开 MUST 有大小与文件数上限，超限整包拒收。

#### Scenario: 一个含 20 份 PDF 的 ZIP

- **WHEN** HR 选择岗位与样本类别后上传一个含 20 份 PDF 的 ZIP
- **THEN** 20 份各自生成简历记录，页面逐文件显示结果

#### Scenario: ZIP 里混有非白名单文件

- **WHEN** ZIP 内含 18 份 PDF、1 份 `.xlsx`、1 份损坏的 PDF
- **THEN** 18 份被接收，`.xlsx` 拒收"不支持的类型"，损坏件拒收"无法读取"

#### Scenario: 超限的 ZIP

- **WHEN** ZIP 展开后文件数超过上限
- **THEN** 整包拒收，不产生任何简历记录

#### Scenario: 嵌套过深

- **WHEN** ZIP 内文件位于两层以上子目录
- **THEN** 这些文件被拒收并提示"目录层级过深"，其余照常

### Requirement: 真实简历入库闸对导出包同样生效

样本类别为 `live` 的导出包 MUST 在展开前求值真实简历入库闸；闸关闭时整包拒收且不落任何文件内容，留痕一次被拒的尝试。

#### Scenario: 闸关闭时上传 live 导出包

- **WHEN** 入库闸关闭，HR 以 `live` 类别上传 ZIP
- **THEN** 整包拒收，不产生简历记录，留痕记录一次被拒尝试

### Requirement: 包内重复文件只入一次

同一 ZIP 内内容哈希相同的两个文件 MUST 只产生一条简历记录，第二个标"包内重复"；与库内既有文件哈希相同的 MUST 返回既有记录并标"重复"。

#### Scenario: 包内两份相同 PDF

- **WHEN** ZIP 内两个文件内容完全相同
- **THEN** 只产生一条简历记录，第二个显示"包内重复"

### Requirement: 展开动作幂等

导出包的接收 MUST 是独占的副作用执行单元，按包内容哈希与岗位幂等；重跑 MUST NOT 产生第二批简历记录。

#### Scenario: 接收节点重跑

- **WHEN** 一个 ZIP 已成功接收，执行单元被从头重跑
- **THEN** 简历记录数不变
