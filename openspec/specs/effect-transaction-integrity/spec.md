## Purpose

保证 effect 层的幂等写入与编排层的检查点持久化在共享同一个数据库连接时，事务边界始终只有一个所有者，异常路径不掩盖原始错误，且该保证可在任意平台确定性验证，不依赖特定运行环境或特定用例名单才能复现。

## Requirements

### Requirement: 单一事务边界所有权

当 effect 层的幂等写入与编排层的检查点持久化共享同一个数据库连接时，该连接上 MUST 只存在一个事务边界的所有者。系统 MUST NOT 出现两个独立组件各自触发 `commit`/`rollback`、且互不知晓对方状态的情况。

#### Scenario: effect 写入与检查点持久化交替执行

- **WHEN** 一次请求处理过程中，先执行一个带幂等保护的 effect 写入，再触发一次编排层的检查点持久化，如此交替多轮
- **THEN** 每一轮的事务提交或回滚都由唯一确定的所有者发起
- **AND** 不出现 "cannot commit - no transaction is active"、"cannot rollback - no transaction is active"、"cannot start a transaction within a transaction" 这类事务状态与实际状态脱节的错误

#### Scenario: 单元测试直接调用 effect 写入函数

- **WHEN** 测试代码在未经过完整编排链路的情况下，直接对同一个连接连续调用多个带幂等保护的写入
- **THEN** 结果与通过完整编排链路调用时一致，不因是否经过检查点持久化而产生不同的事务错误

### Requirement: 异常路径不掩盖原始错误

当一个带幂等保护的写入在执行过程中失败时，系统的兜底清理动作 MUST NOT 抛出掩盖原始异常的新异常。调用方看到的错误 MUST 是导致失败的原始原因。

#### Scenario: 写入失败且连接已无活跃事务

- **WHEN** 一个带幂等保护的写入函数体执行过程中抛出异常，且此时该连接上已没有活跃事务（例如事务已被另一个所有者提前结束）
- **THEN** 系统的兜底清理动作本身 MUST NOT 再抛出异常
- **AND** 调用方最终看到的异常就是写入函数体抛出的原始异常，而不是清理动作产生的次生异常

### Requirement: 幂等键与业务写入原子提交在事务中断后仍然成立

`effect_log` 幂等记录与其对应的业务写入 MUST 在同一个事务边界内提交，即便该连接上还存在其他会主动管理事务的组件（如编排层的检查点持久化）。

#### Scenario: 检查点持久化不打断 effect 的原子性

- **WHEN** 一次带幂等保护的 effect 写入正在进行，编排层在同一连接上触发了一次检查点提交
- **THEN** 该 effect 的业务写入与它对应的 `effect_log` 记录要么一起提交成功，要么一起不提交
- **AND** 不出现业务写入已提交但 `effect_log` 未提交（或反之）的中间状态

#### Scenario: 强制中断后重放验证幂等性

- **WHEN** 一个带幂等保护的 effect 节点在提交前被强制中断，随后编排引擎从该节点开头重新执行（对应工程铁律：LangGraph 恢复时节点从头整个重跑）
- **THEN** 中断前未完整提交的部分写入不可见，重放时该 effect 会被当作首次执行正常完成
- **AND** 重放完成后，该 effect 的业务写入与 `effect_log` 记录都恰好存在一份，不出现重复副作用，也不出现两者数量不一致

### Requirement: 事务归属冲突可在任意平台确定性复现

回归测试 MUST 能够在任意操作系统与任意受支持的 SQLite 版本上稳定复现"单一事务边界所有权"被破坏时的错误，不依赖特定平台环境的偶然时序，也不依赖锁定某几个具体测试用例的名字。

#### Scenario: 本地开发环境可复现

- **WHEN** 在本地开发环境（不限定操作系统）运行该回归测试
- **THEN** 若"单一事务边界所有权"这条保证被破坏，测试 MUST 稳定失败
- **AND** 该复现 MUST NOT 依赖"只在某个特定 CI 平台才会触发"这类偶然条件

#### Scenario: 测试不绑定特定失败用例名单

- **WHEN** 未来的代码改动导致本次修复的问题以不同的执行时序、不同的受害用例重新出现（已观察到同一根因在代码不变的情况下于不同 CI 运行中命中不同的业务测试用例）
- **THEN** 针对本需求编写的回归测试 MUST 直接验证"单一事务边界所有权"这一机制本身
- **AND** MUST NOT 仅通过重跑并断言某几个预先指定的业务测试用例名称通过来判定问题已修复
